# 真实迭代分配设计

## 目标

取消项目级“需求池”默认迭代。每个需求必须归属其项目范围内处于未开始或进行中的真实迭代；创建和修改均不得留空或使用已关闭迭代。

## 数据迁移

迁移会逐项目处理现有需求池。优先选择该项目范围内状态分类为 `normal` 的进行中迭代，兼容历史 `in_progress` 分类；其次选择 `start` 未开始迭代。若两者都不存在，则创建一个使用默认迭代工作流的未开始迭代。需求池内的需求、任务和 Bug 迁移到该目标迭代，并保留迭代历史记录。迁移完成后删除需求池记录及项目到需求池的关联，移除对应的旧模型、服务和数据库字段。迁移按反射得到的约束列精确定位外键和唯一约束，不依赖 MySQL 约束名称。

## 业务约束

项目创建时同步创建一个使用默认迭代工作流的普通未开始迭代，保证新项目立即存在可选真实迭代；该记录可正常编辑和流转，不具有需求池身份或项目指针。需求创建、编辑、批量导入、跨项目移动和迭代关联操作统一调用同一项迭代资格校验：目标迭代存在、属于当前项目或其祖先项目范围、不是关闭状态，且状态分类为 `start`、`normal` 或兼容的历史 `in_progress`。跨项目移动还必须先校验操作者对目标项目的工作项创建权限。缺少迭代或传入已关闭迭代时，后端返回明确的校验错误。任务和 Bug 不再回退到需求池；关联需求或任务时继承其迭代，无关联时使用项目的可用真实迭代，必要时自动创建未开始迭代。显式选择非法迭代时拒绝请求；继承来源已关闭、删除或越界时改用可用真实迭代。从测试用例或测试执行生成 Bug 的入口也必须经过同一回退解析器。需求切换迭代时，关联任务和仍跟随原需求迭代的直接 Bug 在同一事务内同步移动并写入历史。

迭代详情继续提供可用需求和独立任务候选。候选必须位于目标迭代项目范围内、当前归属其他可变的未开始或进行中迭代；关联操作通过统一范围、来源和目标可变性校验完成真实移动，并保留工作项迭代历史。终态来源或目标不允许关联。

## 界面

需求新增和编辑表单只提供当前项目及祖先项目范围内的未开始或进行中迭代，字段为必填且不可清空；项目详情中的新增需求遵循相同规则。项目详情继续展示“待规划工作池”区域，但不再把它当作迭代或筛选入口，而是汇总项目进行中与未开始迭代中的需求、任务和 Bug。原“纳入正式迭代”按钮、事件和属性随需求池移除；迭代详情中的真实迭代移动入口保留。

## 验证

后端 API 测试覆盖项目创建时生成真实未开始迭代、默认工作流启动后的 `normal` 状态、空迭代、关闭迭代、项目外迭代、祖先项目范围、无可用迭代的自动创建、关联字段继承、测试来源 Bug 回退、跨项目权限、真实迭代候选移动、历史闭合及存量迁移；原始工作簿测试不经过自动补列夹具。迁移测试覆盖 MySQL 自动命名约束并在真实 MySQL 临时克隆库执行。前端源级契约测试覆盖必填选择器、可选状态过滤、工作池聚合和旧操作移除。最后运行后端扩展聚焦测试、前端全量测试与生产构建。
