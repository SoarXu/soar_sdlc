# 任务确认处理人路由修复实施计划

**目标：** 使任务提交确认时稳定路由至可用的项目确认人，并在无法解析确认人时阻断流转。

**范围：** 工作流运行时处理人解析、项目成员角色选择和任务工作流 API 测试。

## 步骤

1. 在 `backend/tests/test_requirement_task_api.py` 和 `backend/tests/test_workflow_runtime_api.py` 保留当前两条失败断言，并新增“项目记录负责人不可用但项目确认角色成员可用”与“无确认人时返回 422 且不改变状态”的最小用例。
2. 分别运行两条测试，确认当前实现仍把任务分配给错误的 `Project.owner_id`，或错误放行无确认人流转。
3. 调整 `backend/app/services/workflow_runtime_service.py` 中 `_task_confirmation_owner()`：按任务来源优先级解析；回退到项目级确认人时，从有效项目成员中按确认角色选择，而非直接返回项目记录负责人。
4. 保持 `submit_confirmation` 的既有阻断逻辑，确保解析结果为空且未声明允许无人确认时返回 `422 Confirmation handler is required`，并不提交状态或处理人变更。
5. 运行两处定向测试，验收“待确认”任务的 `owner_id` 为预期确认人；无确认人场景被阻断。
6. 执行 `python -m pytest -q tests/test_requirement_task_api.py tests/test_workflow_runtime_api.py`，再执行全量后端测试。
