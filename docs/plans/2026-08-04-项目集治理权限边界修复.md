# 项目集治理权限边界修复实施计划

**目标：** 恢复项目集、项目治理与工作项操作之间的最小权限边界，阻止跨项目集越权操作。

**范围：** 后端权限服务、项目控制器、业务组件/迭代/评论/关注入口，以及对应 API 回归测试。

## 步骤

1. 在 `backend/tests/test_program_project_api.py` 补充或收紧以下失败场景：无关用户不能在项目集下创建、编辑、移动、管理成员、执行生命周期动作或读取治理审计；项目集负责人仅可治理其项目集下项目的元数据与成员，不可管理工作项、业务组件工作流、评论或关注。
2. 单独执行 `python -m pytest -q tests/test_program_project_api.py`，确认测试因当前越权响应失败。
3. 在 `backend/app/services/project_permission_service.py` 按权限意图拆分创建项目、项目治理、项目配置和工作项访问的判定函数；创建项目必须校验目标项目集的治理权，项目集负责人不能因此取得工作项与业务组件配置权。
4. 在 `backend/app/controllers/project_controller.py` 保留显式传入的 `owner_id` 语义；仅在产品规则允许的场景为创建人默认赋值，避免项目集负责人被无条件设为项目负责人。
5. 检查 `backend/app/controllers/business_component_controller.py`、`iteration_controller.py`、`work_item_comment_controller.py`、`object_watch_controller.py` 的权限调用，改为匹配各自操作等级的校验函数。
6. 重新执行该测试文件及相关权限测试，验收所有越权请求返回 `403`，授权的项目集治理操作仍返回成功。
7. 执行 `python -m pytest -q`，验收全量后端测试通过。
