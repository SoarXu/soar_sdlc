# 后续问题清单

## 使用范围

本文档用于登记 SOAR SDLC 平台后续发现、尚未解决的问题。每一个问题必须先完成复现和影响确认，再建立对应的中文执行计划；未经验证不得标记为已解决。

## 问题状态

- 待确认：已收到现象，尚未稳定复现或确认影响。
- 待计划：已确认问题，等待制定执行计划。
- 待实施：计划已确认，等待集中处理。
- 实施中：正在修复或补充自动化测试。
- 待验证：实现已完成，等待回归与验收。
- 已解决：验证通过，保留问题、计划和验证证据。

- 优先级：P2

- 影响范围：项目详情的测试用例新增和编辑弹窗，以及测试用例详情的编辑与展示界面。

### N-002 需求可落入默认需求池或已关闭迭代

- 状态：待验证
- 类型：功能与数据一致性问题
- 优先级：P1
- 发现时间：2026-08-11
- 影响范围：项目创建、需求创建和编辑、需求导入、迭代工作项关联与移除、任务和 Bug 的迭代继承，以及项目详情的“待规划工作池”展示。
- 复现步骤与证据：创建项目后系统自动生成“需求池”默认迭代；新增需求未选择迭代时会被自动放入该迭代。需求选择器可保留已关闭迭代，项目详情的待规划工作池以默认迭代中的数据为准。
- 预期结果：每个需求必须关联所属项目中进行中或未开始的真实迭代；创建和编辑时不允许为空或选择已关闭迭代。取消默认需求池。既有默认池数据迁移到可用真实迭代，没有可用迭代时自动创建一个未开始迭代。项目详情保留待规划工作池区域，但汇总进行中和未开始迭代中的需求、任务和 Bug。
- 实际结果：默认需求池作为隐藏迭代承接未排期数据，且相关业务入口依赖其作为回退目标。
- 根因分析：需求池被同时用作“未排期数据容器”和“迭代必填约束的技术回退”，导致真实迭代范围、前端选择规则和后端数据规则不一致。
- 执行计划：`docs/plans/2026-08-11-real-iteration-assignment.md`
- 验证结果：后端扩展回归 `cd backend && pytest tests/test_requirement_real_iteration_assignment_api.py tests/test_requirement_pool_repository_contract.py tests/test_requirement_import_api.py tests/test_testing_bug_api.py tests/test_iteration_detail_api.py tests/test_dashboard_workbench_api.py -q` 通过（108 passed），覆盖默认工作流实际启动后的 `normal` 进行中语义、项目及祖先项目迭代范围、需求必填与跨项目权限、显式非法迭代拒绝、终态/删除/越界来源回退、任务和 Bug 关联变更继承、需求移动级联及历史、终态依赖项阻止级联迁出、真实迭代候选与移动、项目待规划汇总、工作台交叉范围、原始导入工作簿，以及迁移约束和测试清理契约。真实 MySQL 临时克隆 59 张表后从 `20260811_001` 升级到 `20260811_002` 通过，旧项目/迭代需求池列已删除，活动需求空迭代数为 0，临时库已清理。`python -m compileall -q app alembic/versions/20260811_002_remove_requirement_pool_iterations.py` 通过。前端全量 `npm test` 通过，`npm run build` 通过（1779 modules transformed）；生产实现已无需求池字段、服务或 `requirementPoolIterations` 命名，项目工作池的旧“纳入迭代”按钮和事件已移除。`git diff --check` 通过，仅有仓库 CRLF 转换提示。当前状态待测试环境产品界面验收。

### N-003 工作台按来源拆分，无法统一查看进行中迭代工作项

- 状态：待验证
- 类型：功能与体验问题
- 优先级：P2
- 发现时间：2026-08-11
- 影响范围：工作台接口、工作台单表展示、工作项筛选和排序、批量指派与工作流操作入口。
- 复现步骤与证据：进入工作台后，需要在“待处理、待分配、我创建、我关注、提及、异常”等入口之间切换；各入口的数据范围不同，不能在同一列表内查看当前用户有权限访问的进行中迭代全部需求、任务和 Bug。
- 预期结果：工作台默认展示当前用户可见、归属进行中迭代的全部需求、任务和 Bug，以一张表按需筛选。已完成或已取消项保留但排序靠后；默认排序为未结束、逾期、高优先级、临近截止日期、最近更新依次优先。
- 实际结果：数据按队列来源拆分，列表默认范围不等同于用户可见的进行中迭代全部工作项。
- 根因分析：工作台 API 和视图模型围绕多个角色队列构建，没有提供权限范围内按迭代聚合的标准工作项集合。
- 执行计划：`docs/plans/2026-08-11-active-iteration-workbench.md`
- 验证结果：后端定向回归 `pytest tests/test_dashboard_workbench_api.py -q` 通过（18 passed）；前端 `npm test` 和 `npm run build` 通过。后端全量 `pytest -q` 结果为 522 passed、93 failed；失败均由现有需求池工作项在流转时要求目标迭代（`TARGET_ITERATION_REQUIRED`）引起，该校验已存在于基线 `HEAD`，属于 N-002 尚未实施的阻塞项，非本条工作台改动引入。

### N-004 工作台列表未占满页面且缺少分页

- 状态：待验证
- 类型：功能与体验问题
- 优先级：P2
- 发现时间：2026-08-11
- 影响范围：工作台进行中迭代工作项列表的页面布局、表格展示、筛选结果和批量选择。
- 复现步骤与证据：进入工作台并加载进行中迭代工作项；列表卡片只占据页面上半部分，表格使用内部纵向滚动，页面下半部分留空；筛选排序后的全部工作项一次性进入表格，没有分页器和每页条数设置。
- 预期结果：列表卡片占满筛选栏以下的剩余可视高度，表格区域自适应填充，分页器固定在卡片底部；默认每页 20 条，可切换 10、20、50、100 条，筛选变化后回到第 1 页，结果减少时自动修正越界页码。
- 实际结果：列表区域未充分使用页面高度，表格依赖内部滚动，且没有分页功能。
- 根因分析：工作台列表容器仍使用内容高度和表格内部滚动约束，筛选排序后的数据直接全部绑定到表格，没有分页状态和切片逻辑。
- 设计说明：`docs/plans/2026-08-11-workbench-pagination-layout-design.md`
- 执行计划：`docs/plans/2026-08-11-workbench-pagination-layout.md`
- 验证结果：严格按 TDD 完成初始实现及审查修复。分页 helper 测试先因缺少 `paginateWorkbenchItems` 导出失败，最小实现后聚焦测试通过，覆盖首/后续页、空列表、无效页码钳制、非正页大小归一、完整分页元数据及输入不可变；审查边界测试又先复现 `Infinity` 和取整后为 0 的正小数被错误接受为页大小，修复后 `Infinity`、`-Infinity`、`NaN`、`Number.MIN_VALUE`、0 到 1 之间的小数、布尔值和非数值字符串均回退默认值，普通数值字符串保持兼容。页面与布局契约测试先因缺少 `currentPage` 等分页状态失败，补齐实现后通过；移动端审查测试随后先复现八个单列筛选器会挤压列表，再改为工作台自身纵向滚动、禁止整页横向溢出，并为列表保留稳定最小高度。工作台表格现仅绑定当前页数据，默认每页 20 条并可切换 10、20、50、100 条；筛选、换页、修改页大小和结果越界校正均清空当前页批量选择。桌面列表卡片使用剩余视口高度，表格在卡片内自适应滚动，分页器稳定置于卡片底部；批量指派条位于表格区域普通文档流中并占用自身高度，不覆盖最后一行或横向滚动条；移动端筛选区与列表可整体纵向滚动，分页 footer 独立横向滚动；空列表仍保留总数为 0 的分页 footer。前端全量 `npm test` 通过，`npm run build` 通过（1779 modules transformed）。当前状态待测试环境产品界面验收。
