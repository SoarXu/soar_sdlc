# 需求任务迭代同步设计

## 背景

需求与其关联任务应属于同一迭代。现有结束迭代校验仅按任务的
`iteration_id` 统计直接任务；当需求已关联迭代、其关联任务未同步迭代时，
任务会从校验与提示中遗漏。

## 方案

在需求与任务的既有迭代归属操作中保持一致：

1. 通过需求创建任务时，任务继承需求的 `iteration_id`。
2. 将需求关联到交付迭代时，将该需求的所有未删除关联任务同步到该迭代。
3. 将需求从交付迭代解绑回需求池时，解除该需求关联任务的迭代归属。
4. 延期需求到目标迭代时，关联任务随需求进入目标迭代。

同步操作复用 `move_work_item_to_iteration`，以保留迭代历史与审计记录。直接
关联到迭代、但不属于该需求的任务不受影响。

## 验证

后端回归测试覆盖任务创建继承、需求绑定同步、需求解绑同步和需求延期同步；
并验证结束迭代的未完成任务统计能包含这些任务。

## 工作台终态标题

工作台仅移除终态工作项标题的删除线，保留灰色文字、终态行背景与状态标签弱化。
此变更只影响工作台中的需求、任务和 Bug 标题，不改变终态的筛选或状态表达。
