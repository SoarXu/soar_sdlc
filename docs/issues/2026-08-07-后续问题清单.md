## 问题状态

- 待确认：已收到现象，尚未稳定复现或确认影响。
- 待计划：已确认问题，等待制定执行计划。
- 待实施：计划已确认，等待集中处理。
- 实施中：正在修复或补充自动化测试。
- 待验证：实现已完成，等待回归与验收。
- 已解决：验证通过，保留问题、计划和验证证据。

## 已解决（本轮）

### N-001 非项目成员可通过业务组件成员关系查看项目及其工作项

- 状态：已解决
- 类型：权限缺陷
- 优先级：P1
- 发现时间：2026-08-07
- 影响范围：项目列表、项目详情、全局需求/任务/Bug 列表、工作台搜索结果、业务组件成员管理，以及项目和工作项详情的直达链接。
- 复现步骤与证据：`InnovateX运维` 项目成员中不包含 `yanan.liu`（刘亚男），但其业务组件 `QA档案管理` 包含该用户。以刘亚男登录后，仍可查看该项目的需求列表及其工作项；进入不属于其项目成员范围的项目或需求详情时，审计相关接口返回 403，页面因并发加载失败而显示不完整数据和“详情加载失败”提示。`shuwan.yang` 因具有 `system_admin` 角色可正常查看。
- 预期结果：项目成员资格是项目数据可见性的前置条件。除系统管理员或明确授予上级治理查看权限的用户外，非项目成员不得在任何列表、搜索结果、工作台或直达链接中看到该项目及其需求、任务、Bug、测试和业务组件。业务组件成员资格仅在该用户已是所属项目成员时用于工作流路由和组件内协作，不得隐式授予项目可见权限。将用户加入业务组件时，系统应校验其已是所属项目成员；否则拒绝保存并要求由有权限的人员先添加项目成员。
- 实际结果：项目、需求等基础列表和详情接口未统一按当前用户的项目可见范围过滤；业务组件成员关系可与项目成员关系不一致。详情页仅在继续请求审计和状态操作接口时执行成员校验，导致非项目成员先看到部分项目数据，再因 403 显示详情加载失败。
- 根因分析：项目访问控制未在后端数据查询边界统一执行，列表、详情和关联资源接口采用了不一致的授权规则；前端将基础详情与受限审计接口通过 `Promise.all` 绑定加载，放大了后端授权不一致造成的展示问题。
- 执行计划：[docs/plans/2026-08-07-project-membership-visibility-implementation.md](../plans/2026-08-07-project-membership-visibility-implementation.md)
- 验证结果：新增非成员不可发现或直达项目、需求、任务、Bug、测试和组件的 API 回归，以及组件创建不复制来源成员的回归；`pytest tests/test_project_permission_boundary_api.py tests/test_business_components_api.py -q` 通过（23 passed）。以真实账号验证：`yanan.liu` 仅能列出项目 2896 及其需求，访问项目 2862 和需求 1171 均返回 403；`shuwan.yang` 仍可访问项目 2862。`python -m compileall -q app` 与 `git diff --check` 通过。
