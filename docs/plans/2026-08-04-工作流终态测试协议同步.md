# 工作流终态测试协议同步实施计划

**目标：** 让工作流运行时测试使用当前终态节点协议，从而恢复其对运行时能力的有效覆盖。

**范围：** `backend/tests/test_workflow_runtime_api.py` 的共享工作流图构造数据。

## 步骤

1. 定位 `_create_project_with_bug_workflow()` 中保存工作流图的终态节点，并保留“未传 `terminal_kind` 返回 422”的已有定义校验测试。
2. 执行 `python -m pytest -q tests/test_workflow_runtime_api.py`，确认 11 项运行时用例在前置建图阶段以同一 `422` 失败。
3. 仅为该共享构造函数的终态节点补充与业务语义一致的 `terminal_kind: completed`，不放宽 `backend/app/services/workflow_definition_service.py` 的生产校验。
4. 再次运行该测试文件，确认此前被前置协议错误遮蔽的运行时测试开始执行；将其余真实失败转交 N-002 或独立问题处理。
5. 执行全量后端测试，验收终态协议校验测试仍覆盖缺失字段的拒绝行为。
