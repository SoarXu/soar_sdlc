# 项目治理权限与默认负责人设计

## 目标

允许任意已登录用户创建项目，默认负责人为创建人且允许修改；统一项目及项目集负责人对下属项目的治理权限。

## 权限规则

- 创建项目：任意已登录用户。
- 默认负责人：请求未指定负责人时，服务端使用当前创建人；前端创建表单预填当前用户，但可修改。
- 项目治理：系统管理员、当前项目负责人、任一上级项目负责人、当前项目集负责人及任一上级项目集负责人。
- 项目治理覆盖编辑、状态变更、项目配置和删除。
- 非系统管理员只能删除无子项目、无工作项的叶子项目；系统管理员可级联删除。
- 在既有项目下新增子项目继续要求父项目治理权限。

## 实现边界

- 在项目权限服务集中实现项目负责人祖先链判断，并与既有项目集治理判断合并。
- 控制器继续通过权限服务校验，避免以页面按钮作为授权依据。
- 创建接口在服务端补齐缺失负责人，前端两个项目创建入口仅提供可编辑的默认值。

## 验证

- 覆盖普通登录用户创建、负责人默认值和显式负责人覆盖。
- 覆盖项目负责人祖先、项目集负责人祖先对配置与删除的治理权限。
- 覆盖不相关用户被拒绝。
