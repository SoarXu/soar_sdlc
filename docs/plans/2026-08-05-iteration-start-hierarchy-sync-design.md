# 迭代启动层级同步设计

## 目标

消除“迭代进行中、关联项目和项目集仍规划中”的状态矛盾，使迭代启动成为关联交付层级的实际启动信号。

## 规则

- 仅在交付迭代执行 `start` 工作流动作时生效；需求池、完成和取消动作不触发同步。
- 系统锁定迭代关联的全部项目及其所属项目集祖先。
- 任一关联项目处于关闭终态，或任一项目集已关闭时，拒绝迭代启动，且不修改任何状态或日期。
- 对仍处于规划中的关联项目，使用其当前工作流的 `start` 动作在同一事务内启动；对已进行中的项目保持不变。
- 将每个被启动项目所属的项目集和祖先项目集同步为进行中；尚未填写实际开始日期时，使用迭代的实际开始日期。
- 一次迭代启动产生的项目状态操作保留执行该迭代动作的操作人和“迭代启动同步”来源信息。

## 范围

- 修改工作流运行时的迭代启动路径及项目集同步辅助逻辑。
- 增加后端 API 回归测试。
- 不改变手动项目启动、项目集手动启动、迭代完成/取消、工作项流转或前端按钮展示。

## 事务与错误处理

在写入迭代状态前完成全部父级状态校验；项目启动、项目集启动、迭代状态操作及日期写入使用同一个数据库事务。发现关闭父级、缺少可执行项目启动动作或任一项目同步失败时，整体回滚并返回明确的中文错误信息。

## 验证

覆盖单项目、多项目、已进行中项目、关闭项目集和关闭项目五种场景；验证成功场景的迭代、项目、项目集状态与开始日期，以及失败场景不存在部分更新。
