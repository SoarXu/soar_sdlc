# 后续问题清单

## 使用范围

本文件用于登记 SOAR SDLC 平台后续发现、尚未解决的问题。每个问题必须先完成复现和影响确认，再建立对应的中文执行计划；未经验证不得标记为已解决。

## 问题状态

- 待确认：已收到现象，尚未稳定复现或确认影响。
- 待计划：已确认问题，等待制定执行计划。
- 待实施：计划已确认，等待集中处理。
- 实施中：正在修复或补充自动化测试。
- 待验证：实现已完成，等待回归与验收。
- 已解决：验证通过，保留问题、计划和验证证据。

## 已解决（本轮）

### N-001 迭代生命周期动作收进更多菜单

- 状态：已解决
- 类型：体验问题
- 优先级：P2
- 发现时间：2026-08-05
- 影响范围：迭代详情页、迭代列表，以及项目详情页的迭代操作列。
- 复现步骤与证据：创建或打开处于“规划中”的迭代；在上述任一入口中查看操作区，“开始”显示在“更多”下拉菜单内。迭代进入“进行中”后，“完成”和“取消”同样受该菜单分组影响。
- 预期结果：迭代在任一入口中只要存在当前可执行的生命周期动作（开始、完成或取消），均直接显示为操作按钮，不显示“更多”菜单。
- 实际结果：通用工作流动作组件未按详情或迭代对象区分分组；迭代动作遵循默认的“更多操作”分组，导致生命周期动作被收进下拉菜单。
- 根因分析：`WorkflowActionButtons.vue` 对所有模式调用 `splitListActions()`；该函数仅对项目对象的少数动作设为直显，迭代对象仍完全依赖 `list_display` 配置。默认迭代动作未配置为主操作。
- 执行计划：`docs/plans/2026-08-05-iteration-actions-direct-display.md`
- 验证结果：`node src/utils/workflowRuntimeActions.test.mjs`、前端 `npm test`（12/12）及 `npm run build` 均通过；迭代动作及自定义迭代动作均进入直显操作，`moreActions` 为空。

### N-002 Bug 类型在列表和详情中显示技术代码

- 状态：已解决
- 类型：体验问题
- 优先级：P2
- 发现时间：2026-08-05
- 影响范围：项目详情的 Bug 列表、迭代详情的 Bug 列表，以及 Bug 详情基础信息区。
- 复现步骤与证据：创建或打开 `bug_type` 为 `code_issue` 的 Bug；项目详情和迭代详情的列表均直接显示 `code_issue`，Bug 详情的基础信息区未展示 Bug 类型。
- 预期结果：两个列表和 Bug 详情均使用 Bug 类型字典中的中文名称，例如将 `code_issue` 显示为“代码问题”。
- 实际结果：两个列表直接渲染 `row.bug_type`，Bug 详情未包含类型字段；已存在的 `bugTypeLabel()` 未用于这些展示位置。
- 根因分析：三处页面已通过 `useBugTypes()` 获取类型字典以支持编辑表单，但展示模板未调用该组合式函数提供的中文标签映射。
- 执行计划：`docs/plans/2026-08-05-bug-type-chinese-labels.md`
- 验证结果：`node src/views/bugTypeDisplay.test.mjs`、前端 `npm test`（12/12）及 `npm run build` 均通过；两处列表和 Bug 详情均调用 `bugTypeLabel()` 显示字典中文名称。

### N-003 Bug 列表操作列宽度不足导致按钮截断

- 状态：已解决
- 类型：体验问题
- 优先级：P2
- 发现时间：2026-08-05
- 影响范围：全局 Bug 列表的固定“操作”列。
- 复现步骤与证据：在 Bug 列表打开存在“认领”等主操作的记录；该行同时显示“关注”“认领”“更多”和“删除”时，固定操作列右侧的删除按钮被截断。
- 预期结果：当前用户有权限看到的关注、工作流动作、更多和删除按钮始终在同一行完整可见。
- 实际结果：`BugsView.vue` 仅为工作流动作以外的操作预留 `90px`，实际的关注按钮、删除按钮及两段间距约需 `160px`，导致列宽不足。
- 根因分析：`WatchToggleButton.vue` 的最小宽度为 `92px`；`workflowActionColumnWidth()` 只计算工作流动作。Bug 页面传入的 `extraWidth` 未覆盖删除按钮与外层 `table-actions` 间距。
- 执行计划：`docs/plans/2026-08-05-bug-list-action-column-width.md`
- 验证结果：`node src/views/bugListActionColumnWidth.test.mjs`、`node src/utils/workflowActionColumn.test.mjs`、前端 `npm test`（12/12）及 `npm run build` 均通过；紧凑主操作加“更多”场景的动态列宽为 `268px`。

### N-004 启动迭代未同步启动关联项目及项目集

- 状态：已解决
- 类型：数据问题
- 优先级：P1
- 发现时间：2026-08-05
- 影响范围：交付迭代的生命周期、关联项目及其所属项目集树。
- 复现步骤与证据：在项目和项目集均为“规划中”时，启动关联该项目的交付迭代；迭代已进入“进行中”并记录实际开始日期，但项目和项目集仍显示“规划中”。截图中的“20260804-项目一”及其项目集“20260804”即为该状态组合。
- 预期结果：启动迭代时，系统在同一事务内启动仍处于规划中的关联项目，并同步启动这些项目所属的项目集及其祖先；任一关联项目或项目集已关闭时，拒绝启动迭代且不产生部分状态变更。
- 实际结果：通用工作流运行时仅校验迭代不是需求池并更新迭代自身状态和实际开始日期，未校验或同步关联项目、项目集状态。
- 根因分析：项目启动的旧服务路径包含 `_activate_program_tree()`，但页面使用的 `/workflow-runtime/iteration/{id}/transition` 通用路径未复用该层级同步逻辑；迭代 `start` 动作也没有父级状态校验。
- 执行计划：`docs/plans/2026-08-05-iteration-start-hierarchy-sync.md`
- 验证结果：`pytest backend/tests/test_iteration_detail_api.py -q` 通过（32 passed）；覆盖关联项目及项目集祖先同步、多项目、已进行中项目保持不变并回填项目集开始日期、关闭父级拒绝且无部分更新。
