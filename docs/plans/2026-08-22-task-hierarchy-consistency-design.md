# 任务层级与需求任务一致性设计

## 背景

当前任务是扁平结构。`tasks` 表没有父任务字段，任务创建和读取接口无法表达上下级关系，任务详情也没有子任务入口。任务工作流在进入完成或取消终态时不检查下级任务，因此即使未来只增加父任务字段，也会出现父任务结束、子任务仍在执行的数据矛盾。

现有系统已经具备部分需求任务联动：从需求创建任务时继承需求迭代，需求移动时同步直接关联任务。但该联动只覆盖直接任务，普通任务创建接口没有完整保证任务与需求同项目，任务也可能被单独移入其他迭代。加入多级子任务后，这些缺口会放大。

N-002 将工作项状态与处理人、迭代阶段对齐。N-005 的层级移动必须复用 N-002 的正式状态流转和审计机制，不能直接批量覆盖 `current_state_id`。

## 目标

- 任务支持任意层级的父子关系，并从任务详情创建和查看直接子任务。
- 一棵任务树始终共享同一 `project_id`、`requirement_id` 和 `iteration_id`。
- 关联需求的任务树始终与需求属于同一项目和迭代。
- 根任务或关联需求移动时，整棵任务树在同一事务中移动并执行 N-002 状态联动。
- 父任务进入完成或取消终态前，递归检查全部后代任务是否均已完成或已取消。
- 阻断响应提供可操作的未结束子任务清单，前端统一展示，不自动修改子任务状态。

## 非目标

- 不提供跨项目任务树。
- 不允许一棵任务树关联多个需求。
- 不自动汇总工时、进度百分比或处理人。
- 不在本问题中实现批量创建子任务、拖拽调整层级或任务树甘特图。
- 不自动完成或取消子任务。
- 不重复实现 N-002 的状态矩阵、迭代启动或状态迁移逻辑。

## 方案选择

### 方案一：自关联父任务外键与递归查询

在 `tasks` 增加可空的 `parent_task_id`，根任务为空，子任务指向直接父任务。服务层集中维护层级约束，使用递归 CTE 或受控遍历读取后代。结构简单、写入成本低，适合当前以详情和终态校验为主的访问模式。

### 方案二：通用对象关系表

使用 `object_relations` 保存任务父子关系。虽然无需新增任务列，但数据库无法用普通外键表达唯一父任务，也更难阻止多父、循环和跨项目关系；高频层级查询还要额外过滤关系类型。

### 方案三：闭包表

维护祖先、后代和深度的闭包表，查询很快，但每次创建、移动或删除层级都要维护多行关系。当前没有重排层级和大规模树统计需求，复杂度超出范围。

采用方案一。`parent_task_id` 是任务自身核心结构，不应伪装成通用关联关系。

## 数据模型

为 `tasks` 增加：

```text
parent_task_id BIGINT NULL
FOREIGN KEY -> tasks.id ON DELETE RESTRICT
INDEX(parent_task_id)
CHECK(parent_task_id IS NULL OR parent_task_id <> id)
```

存量任务全部作为根任务，`parent_task_id=NULL`。跨行不变量由服务层校验：

- 父任务必须存在且未删除。
- 子任务与父任务的项目、需求、迭代完全一致。
- 新建子任务只能指定直接父任务；创建后 `parent_task_id` 不可修改，避免重挂导致循环或跨聚合迁移。
- 删除存在未删除子任务的父任务时返回冲突，防止软删除后形成不可见父节点。

`TaskCreate` 增加 `parent_task_id`；`TaskUpdate` 不开放该字段。`TaskRead` 返回 `parent_task_id`、父任务摘要和直接子任务数量。直接子任务通过独立分页接口读取，避免每个任务响应递归嵌套整棵树。

## 聚合一致性

### 创建子任务

用户从父任务详情点击“新增子任务”。后端以父任务为权威来源，覆盖客户端传入的项目、需求和迭代：

```text
child.project_id = parent.project_id
child.requirement_id = parent.requirement_id
child.iteration_id = parent.iteration_id
```

客户端只提交子任务业务字段和 `parent_task_id`。处理人仍可独立选择，初始状态由 N-002 根据继承迭代的阶段和处理人决定。

### 根任务关联需求

- 根任务关联需求时，需求必须未删除，任务树项目和迭代同步为需求的项目和迭代。
- 根任务切换需求时，整棵树统一切换 `requirement_id`、项目和迭代。
- 根任务取消需求关联时，整棵树统一清空 `requirement_id`，但保留当前项目和迭代。
- 子任务不得独立修改项目、需求或迭代。

### 移动需求或独立任务树

- 需求移动项目或迭代时，收集其全部根任务及后代，完成权限、目标迭代和 N-002 状态可迁移性预检后，再统一写入。
- 独立根任务移动时，同样收集整棵树；子任务不能作为独立移动入口。
- 所有节点预检通过后才开始变更；任一节点失败则整个事务回滚。
- 每个被移动任务均调用统一迭代历史和 N-002 状态联动服务，保留逐项审计证据。
- `source_project_id` 继续表示业务组件来源，不作为任务实际项目一致性的判断字段。

## 终态约束

新增任务后代终态校验器，挂载到默认任务工作流中所有进入“已完成”或“已取消”终态的流转。校验根据目标状态的稳定终态语义触发，不只依赖 `complete`、`cancel` 等动作名称，兼容不同任务分支和管理员可配置动作。

校验递归读取全部未删除后代，允许状态为：

- 完成终态；
- 取消终态。

存在其他状态时返回结构化 `409`：

```json
{
  "code": "TASK_DESCENDANTS_NOT_TERMINAL",
  "message": "存在未结束子任务，当前任务无法完成或取消。",
  "counts": { "task": 2 },
  "blockers": [
    { "id": 18, "title": "接口联调", "status_name": "处理中", "parent_task_id": 12 }
  ]
}
```

只阻断当前父任务流转，不自动执行任何后代流转。叶子任务不产生额外查询结果即可通过。

## 接口与前端

### 后端接口

- `POST /tasks`：支持 `parent_task_id`，创建子任务时归属字段由父任务决定。
- `GET /tasks/{task_id}`：返回父任务摘要及直接子任务数量。
- `GET /tasks/{task_id}/children`：分页返回直接子任务，沿用任务可见性和项目权限。
- `PATCH /tasks/{task_id}`：根任务可调整需求或迭代并同步任务树；子任务提交项目、需求、迭代变更时返回 `409`。

### 任务详情

- 标题区显示父任务链接，便于返回上级。
- 增加“子任务”区，展示标题、处理人、状态、迭代和详情链接。
- 有任务创建权限且任务未处于终态时显示“新增子任务”。
- 新增表单默认继承且只读展示项目、需求和迭代，只允许填写标题、任务分支、处理人、优先级、截止日期和描述。

全局任务列表与项目详情任务列表暂不渲染完整树，避免改变分页语义；可增加父任务标识或链接，但分页仍以任务行为单位。

### 阻断展示

`WorkflowActionButtons` 识别 `TASK_DESCENDANTS_NOT_TERMINAL`，复用现有阻断详情对话框展示子任务清单和详情链接。列表、详情和项目详情中的工作流按钮得到一致反馈。

## 权限与并发

- 创建子任务沿用父任务项目的任务创建权限。
- 查看父子关系必须同时通过任务所在项目的查看权限。
- 移动需求或根任务树按目标项目重新校验任务创建/管理权限。
- 聚合预检与写入位于同一数据库事务；更新根任务、需求及后代时锁定相关行，防止校验后有新子任务插入或状态变化。
- 创建子任务时锁定父任务，若父任务已进入终态或正在迁移则拒绝创建。

## 迁移与兼容

- Alembic 增加可空字段、索引、自关联外键和自指检查；不推断历史父子关系。
- 默认任务模板增加后代终态校验配置；服务器已有受管默认任务工作流通过幂等迁移补齐。
- 自定义工作流不自动改写。运行时仍可基于目标终态执行平台级最低保护，或在工作流设计器中显式配置校验；实施时以现有工作流扩展约定为准并通过测试锁定。
- API 新字段均为向后兼容的可空字段，旧客户端仍可创建根任务。

## 实施顺序

1. 完成 N-002 并提供可复用的迭代移动状态联动服务。
2. 增加任务自关联字段和只读层级查询。
3. 实现创建子任务及聚合一致性校验。
4. 扩展需求和根任务移动，使其原子同步完整任务树。
5. 增加任务后代终态校验和既有默认工作流迁移。
6. 完成任务详情子任务体验及阻断展示。
7. 执行迁移、API、工作流、并发和浏览器验收。
