# 任务层级与需求任务一致性验证计划

## 验证目标

确认任意层级子任务能够安全创建和查看，任务树与关联需求始终保持同项目、同需求、同迭代；需求或根任务移动时整棵树原子同步并遵循 N-002 状态矩阵；父任务完成或取消时能够递归阻断未结束后代，且不会自动修改子任务状态。

## 验证类型与依据

本计划属于功能与回归验证计划，不是 SAT 现场验收文件。依据为用户确认规则与现有代码组合，正式执行时由自动化测试和浏览器验收共同提供证据。

| 依据编号 | 来源定位 | 已确认或已观察规则 |
|---|---|---|
| R-001 | `docs/issues/2026-08-22-后续问题清单.md` N-005 | 支持任意层级子任务；父任务完成/取消前递归检查全部后代，不自动级联状态。 |
| R-002 | 用户 2026-08-22 确认 | 一棵任务树共享同一项目、需求和迭代，子任务不得单独脱离。 |
| R-003 | 用户 2026-08-22 确认 | 需求和关联任务必须同项目、同迭代；移动按整棵树原子执行。 |
| R-004 | `backend/app/models/task.py` `Task` | 当前无 `parent_task_id`，存量任务均应迁移为根任务。 |
| R-005 | `backend/app/services/task_service.py` `create_task/update_task` | 当前从需求继承迭代，但普通入口缺少完整任务树一致性约束。 |
| R-006 | `backend/app/services/work_item_iteration_history_service.py` `move_requirement_dependents_to_iteration` | 当前需求移动同步直接关联任务，需扩展到所有后代并保留历史。 |
| R-007 | `backend/app/services/workflow_runtime_service.py` `_run_transition_validators` | 已有需求、Bug、迭代和项目终态校验模式，可扩展任务后代校验。 |
| R-008 | N-002 设计及实现结果 | 迭代阶段和处理人决定任务状态；层级移动必须复用正式流转及审计。 |

## 验证前提

- N-002 已实现并通过验证，能够按稳定角色识别待分派、待开始和处理中。
- 测试数据库已升级到 N-005 两个 Alembic 修订，`alembic current` 只显示一个 head。
- 准备项目负责人、普通项目成员和非项目成员三个账号。
- 准备未开始迭代 A、进行中迭代 B，以及一个不可接收移动的终态迭代。
- 准备需求 R1，并创建三层任务树：根任务 T1、子任务 T2、孙任务 T3。
- 浏览器开发者工具可以检查任务创建、更新、工作流流转和子任务查询请求。

## 自动化验证

运行：

```bash
cd backend
pytest tests/test_task_hierarchy_migration.py tests/test_task_descendant_terminal_gate_migration.py -v

alembic current
```

- `parent_task_id` 可空、有索引、自关联外键和禁止自指检查。

- 默认受管任务工作流补齐后代终态校验且不产生重复配置。

## 功能验收矩阵

| 用例 | 依据 | 场景与步骤 | 预期结果 |
|---|---|---|---|
| N005-F-001 | R-001、R-002 | 打开 T1 详情，点击“新增子任务”，填写 T2；再从 T2 创建 T3。 | T2 的父任务为 T1，T3 的父任务为 T2；每级详情仅列出直接子任务，并可沿父任务链接返回。 |
| N005-F-002 | R-002、R-003 | T1 关联 R1，在未开始迭代 A 中创建 T2/T3。 | 三个任务的项目、需求、迭代与 R1 完全一致；继承字段只读。 |
| N005-F-003 | R-008 | 分别创建无处理人和有处理人的子任务。 | 状态符合 N-002：无处理人为待分派，有处理人在未开始迭代为待开始。 |
| N005-F-004 | R-002、R-003、R-006 | 将 R1 从未开始迭代 A 移入进行中迭代 B。 | R1、T1、T2、T3 在同一事务中进入 B；每项都有迭代历史；有处理人的任务按 N-002 进入处理中。 |
| N005-F-005 | R-002、R-008 | 移动未关联需求的根任务 T1 到迭代 B。 | 整棵任务树同步移动并按各自处理人更新状态，子任务不能遗漏。 |
| N005-F-006 | R-001、R-007 | T2 或 T3 仍为非终态时，尝试完成 T1。 | 返回 `TASK_DESCENDANTS_NOT_TERMINAL`；阻断对话框列出所有未结束后代及状态；T1 和后代状态均不变。 |
| N005-F-007 | R-001、R-007 | T2 或 T3 仍为非终态时，尝试取消 T1。 | 与完成使用同一阻断规则，不自动取消任何后代。 |
| N005-F-008 | R-001 | 将 T2 完成、T3 取消后，再完成或取消 T1。 | 终态流转成功；已结束后代状态不发生额外变化。 |
| N005-F-009 | R-001、R-007 | 对没有子任务的叶子任务执行完成或取消。 | 不出现后代阻断，沿用原工作流结果。 |
| N005-F-010 | R-002 | 根任务切换到同项目同迭代的另一需求。 | 整棵任务树统一切换需求；不存在一棵树关联多个需求。 |
| N005-F-011 | R-002 | 根任务取消需求关联。 | 整棵树的需求关联同时清空，项目和迭代保持一致且不变。 |

## 异常与边界验证

| 用例 | 依据 | 场景与步骤 | 预期结果 |
|---|---|---|---|
| N005-E-001 | R-002 | 直接 PATCH 子任务，尝试修改项目、需求或迭代。 | 返回 `409 CHILD_TASK_SCOPE_IMMUTABLE`，所有字段保持原值。 |
| N005-E-002 | R-002 | 创建子任务时伪造不同项目、需求或迭代。 | 后端以父任务归属为准或明确拒绝；不能生成不一致数据。 |
| N005-E-003 | R-001 | 在已完成、已取消或已删除父任务下创建子任务。 | 请求失败并返回明确中文错误，不创建任务或历史。 |
| N005-E-004 | R-004 | 尝试将任务设为自己的父任务，或通过直接数据库测试构造循环。 | 数据库/服务拒绝；层级查询不会无限递归。 |
| N005-E-005 | R-003、R-008 | 整棵树移动时令一个后代处于 N-002 禁止回退的执行中状态。 | 返回包含该后代的阻断清单；需求、所有任务和历史记录均无部分更新。 |
| N005-E-006 | R-003 | 将需求或根任务树移动到关闭、删除或越界迭代。 | 整体拒绝，错误指明目标迭代不可用。 |
| N005-E-007 | R-001 | 父任务拥有 0、1、三层及多分支后代，分别执行终态校验。 | 0 个直接通过；其他情况完整识别所有非终态后代，不重复、不遗漏。 |
| N005-E-008 | R-001 | 某后代已软删除，其余后代均为终态。 | 已删除任务不作为阻断项；父任务可以结束。 |
| N005-E-009 | R-002 | 尝试删除仍有未删除直接子任务的父任务。 | 返回冲突，父任务和子任务均保持可见。 |
| N005-E-010 | R-003 | 同时发起“为 T1 新建子任务”和“移动 T1 所在任务树”。 | 行锁保证一种操作先完成；最终新子任务与整棵树归属一致，不出现孤立或跨迭代节点。 |

## 迁移与兼容验证

1. 在生产结构副本上记录升级前任务数、工作流定义数和状态历史数。
2. 执行 `alembic upgrade head`，核对计数不减少，历史任务全部为根任务。
3. 再次执行受管默认工作流对齐函数，确认终态校验配置不重复。
4. 使用旧版创建根任务请求，不传 `parent_task_id`，确认仍可成功。
5. 验证管理员自定义任务工作流未被数据迁移覆盖动作、布局或权限。
6. 执行一次升级后的需求移动，确认历史数据任务与新任务遵守相同聚合规则。

## 浏览器验收路径

1. 使用项目负责人进入 T1 详情，创建 T2 和 T3，验证父子导航和继承字段。
2. 在需求详情或迭代入口移动 R1，观察 T1/T2/T3 的迭代和状态同时变化。
3. 尝试单独编辑 T2 的需求或迭代，确认界面不可编辑且接口无法绕过。
4. 保持 T3 处理中，分别点击 T1 的完成和取消，核对阻断清单及详情跳转。
5. 完成或取消所有后代后再次结束 T1，确认流转成功。
6. 使用无创建权限和非项目成员账号复验按钮可见性及接口权限。
7. 在网络面板确认创建、移动和工作流请求没有重复提交，失败移动没有后续部分写入请求。
