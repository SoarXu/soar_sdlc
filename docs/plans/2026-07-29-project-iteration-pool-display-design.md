# 项目迭代列表需求池展示设计

## 目标

项目详情的迭代列表必须显示该项目的需求池。需求池固定显示在列表第一行，供项目成员识别未排期需求的归属；它仍不是交付迭代，不参与工作台、统计、延期或全局迭代列表。

## 展示规则

- 项目迭代分页接口返回该项目的规范需求池和普通交付迭代。
- 前端从接口结果中识别 `is_requirement_pool = true` 的记录，将其固定置顶；普通迭代保留既有排序与分页语义。
- 需求池名称按用户保存的实际名称展示，并附加“未排期”语义标签。
- 项目详情以外的全局迭代列表、Bug/测试迭代选择、延期目标、工作台、燃尽图和交付统计继续排除需求池。

## 编辑规则

- 需求池行保留列表中的“编辑”按钮，复用普通迭代编辑弹窗。
- 打开需求池编辑时，只有名称字段可编辑；负责人、日期、目标、生命周期阶段和关联项目范围均禁用。
- 保存请求仅提交 `{ name }`；服务端现有需求池保护规则仍是最终边界，拒绝其他字段修改。
- 普通迭代的编辑弹窗、操作按钮与权限不改变。

## 数据流

1. 项目详情加载迭代分页数据时，后端包含需求池。
2. 前端提取需求池并置于普通迭代分页行之前。
3. 用户在需求池行点击编辑，表单进入只改名称模式。
4. 保存后调用现有迭代更新接口，刷新项目迭代数据与需求选择项。

## 验收与测试

- 项目迭代列表始终在第一行显示一个需求池，普通迭代列表不包含重复需求池。
- 需求池编辑弹窗只有名称可修改，保存负载不含受保护字段。
- 普通迭代编辑行为不回归。
- 全局迭代列表和交付范围入口仍不显示需求池。
- 后端分页、前端展示排序和源代码契约测试覆盖上述规则。
