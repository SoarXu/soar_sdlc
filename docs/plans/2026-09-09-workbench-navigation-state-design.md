# 工作台导航状态保持设计

## 背景

工作台的筛选条件和分页当前只保存在 `DashboardView.vue` 的本地响应式状态中。进入需求、任务或 Bug 详情后，工作台组件卸载；返回或再次进入时状态重新初始化，导致用户丢失当前工作上下文。

## 目标

- 从需求、任务、Bug 详情页返回工作台时，恢复离开前的筛选条件、当前页和每页条数。
- 浏览器前进/后退时，工作台状态由历史 URL 恢复。
- 通过侧边栏离开后再次进入工作台时，继续保留当前状态。
- 用户主动清空单项筛选或执行重置时，状态按用户操作更新。

## 方案

使用工作台 URL 查询参数作为状态源：

- `keyword` 保存关键词。
- `project_ids`、`iteration_ids`、`object_types`、`state_ids`、`priorities`、`handler_ids` 保存多选筛选值。
- `page` 保存当前页，`page_size` 保存每页条数。

工作台首次挂载时从当前路由解析参数并初始化本地 refs；筛选变化使用 `router.replace` 更新当前工作台历史记录，避免每次输入都新增浏览器历史项；分页变化同样同步 URL。进入详情时沿用当前工作台查询参数，详情页返回时导航到带原查询参数的工作台路由。由于状态位于 URL，侧边栏离开后再次进入仍可恢复，刷新和浏览器前进/后退也能恢复。

## 边界与错误处理

- 缺失或非法分页参数回退到 `page=1`、`page_size=20`。
- 多选参数统一使用可重复查询参数或稳定的逗号分隔格式，并过滤空值。
- 后端返回实际页码时同步本地分页状态和 URL，避免筛选结果减少后出现空页。
- 不把临时选中行、弹窗内容等 UI 瞬时状态写入 URL；进入详情前清除选择仍由现有逻辑负责。

## 测试策略

- 添加纯函数测试，覆盖状态序列化/解析、非法值回退和多选字段往返。
- 添加视图契约测试，确认工作台从路由初始化、筛选/分页同步 URL，以及详情链接携带工作台查询参数。
- 运行前端完整测试和生产构建。
