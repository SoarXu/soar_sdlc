# 项目迭代操作列动态宽度设计

## 目标

避免项目详情迭代列表的操作列因固定宽度不足而截断“完成、取消、延期工作项、编辑、删除”等操作。

## 方案

将迭代操作列由固定 `250px` 改为计算属性。复用 `workflowActionColumnWidth` 计算当前页迭代的运行时工作流动作宽度，并为延期工作项、编辑、删除三个本地操作预留固定空间；取所有当前行的最大值，且设置足以容纳当前常见动作组合的最小宽度。

需求池、权限条件、动作顺序和后端接口均不改变。

## 验证

增加项目详情迭代布局源码契约：操作列绑定动态宽度属性，且该属性使用 `workflowActionColumnWidth` 计算。先验证旧固定列失败，实施后运行完整前端测试与生产构建。
