# Code Review 状态改名设计

## 背景

当前启用的“默认工作流规则”方案以及系统默认模板中，需求、任务和缺陷的评审状态均显示为“待评审”。主上要求统一显示为 `Code Review`，用于在流程图、列表和详情页中明确区分评审阶段。

本次只改状态显示名称，不调整评审动作、状态身份、路由、权限、处理人规则或审计规则。项目工作流没有评审状态，不在范围内。

## 范围

- 对象类型：需求、任务、缺陷。
- 状态：名称精确为“待评审”的状态节点。
- 存量定义：系统默认模板与所有已保存的需求、任务、缺陷工作流定义。
- 新建定义：内置模板和默认模板协调逻辑均创建或保留 `Code Review` 节点。

## 设计

### 状态身份和流转不变

评审节点继续由既有稳定流转键识别：`submit_review` 指向该节点，`approve_review` 与 `reject_review` 从该节点出发。状态 ID、`pending_review` 模板引用、`state_role`、启用状态以及全部流转的来源/目标 ID 均不变。

“提交评审”“评审通过”“评审驳回”仍保持原名称和权限。工作项历史、状态操作快照和既有评审记录不回写，确保审计信息保留发生时的文案。

### 存量数据迁移

新增 Alembic 数据迁移，精确更新 `workflow_states` 中满足下列条件的记录：

- 所属定义对象类型为 `requirement`、`task` 或 `bug`；
- 当前 `status_name` 为“待评审”。

更新值为 `Code Review`。该 SQL 只影响当前节点显示名，幂等地跳过已改名或其他自定义名称的状态。降级为非破坏性 no-op：迁移无法可靠区分本次改写的记录和迁移前已有的自定义 `Code Review` 状态，不能冒险把后者改为旧名称。

### 模板与协调逻辑

默认需求、任务、缺陷图中 `pending_review` 节点的显示名改为 `Code Review`。`reconcile_review_subgraph()` 同时识别旧名称与新名称；若发现旧名称，原地改名而不创建第二个评审节点，确保后续启动协调与新数据迁移一致。

## 验证

- 纯模板测试：三种默认图的 `pending_review` 显示为 `Code Review`，且三条评审流转仍指向同一节点。
- 迁移测试：断言迁移修订号、上下游依赖和精确对象类型/名称条件；使用临时数据库验证三个对象类型被更新，项目和非目标名称不受影响，升级/降级均可执行。
- API 回归：系统默认图读取结果中包含 `Code Review`，不再包含“待评审”；评审提交后的工作项状态名为 `Code Review`。
- 运行验证：升级本地数据库后查询当前启用方案的三个定义，确认状态 ID 和评审流转 ID 不变、名称已更新。
