# 组件事项手动指派候选范围设计

## 背景

需求、任务或缺陷绑定主业务组件后，组件成员和组件工作流应构成该事项的流转边界。当前运行时仅在为当前流转配置了组件专属路线时限制手动指派候选人；若该路线不存在，会退回查询项目成员，可能把不属于组件的项目成员暴露为候选人。

## 目标

对于绑定主组件的事项，手动指派候选人始终仅来自该组件的启用成员。无主组件的事项继续遵循现有项目成员规则。

## 方案

保留组件专属流转路线的最高优先级：当路线存在时，继续使用路线已计算出的候选人。路线不存在但事项绑定主组件时，运行时读取该组件的启用成员，并将通用规则的 `manual_owner_roles`（或其现有等价配置）作为组件角色过滤条件：

- 配置了具体角色时，仅返回 `component_role` 命中的组件成员；
- 未配置角色，或配置包含 `project_member` 时，返回全部启用组件成员；
- 不再查询项目成员作为候选人兜底；
- 组件成员为空或角色不匹配时，返回空候选列表。

不改变现有组件专属路线、组件执行权限、事项创建、项目成员或未绑定组件事项的处理逻辑。

## 验证

新增 API 回归测试：组件创建后将一名同角色的来源项目成员移出组件团队，并创建绑定组件的需求。对手动指派候选人断言其包含组件成员、排除该非组件成员。该测试在修复前应失败，修复后通过；随后执行该测试模块和前端构建，确认后端行为及前端契约未受影响。
