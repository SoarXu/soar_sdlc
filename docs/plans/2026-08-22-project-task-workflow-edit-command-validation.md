# 项目详情任务编辑命令验证计划

## 验证目标

确认项目详情任务编辑入口完全由工作流动作控制，主操作和更多操作均能打开现有编辑弹窗，不再出现固定编辑按钮与工作流编辑动作重复；同时确认删除操作、其他页面和 Bug 现有编辑能力未受影响。

## 验证前提

- 使用包含项目详情、任务工作流配置和任务编辑权限的测试账号。
- 准备一个包含“待分派”任务的项目，并确认该项目绑定的任务工作流已启用。
- 至少准备三种编辑动作配置快照：`primary`、`more`、当前状态无 `edit` 动作。
- 浏览器开发者工具可以查看 `/api/v1/workflow-runtime/...` 和任务更新请求。
- 验证过程中不得创建白名单外测试用户。

## 页面验收矩阵

| 场景 | 工作流配置 | 预期入口 | 点击结果 |
|---|---|---|---|
| 主操作编辑 | `edit.list_display=primary` | 操作列直接显示一个“编辑” | 打开当前任务编辑弹窗 |
| 更多编辑 | `edit.list_display=more` | 操作列不直接显示编辑；“更多”中显示一个“编辑” | 打开当前任务编辑弹窗 |
| 无编辑动作 | 当前状态不返回 `edit` 或动作被停用 | 操作列和“更多”均无编辑 | 无编辑入口 |
| 无编辑权限 | 当前账号不满足动作允许角色 | 不显示编辑动作 | 无越权入口 |
| 页面固有删除 | 用户具备删除权限 | 删除按钮继续显示 | 仍走原删除确认与接口 |

## 浏览器详细步骤

### 场景 A：编辑配置为更多操作

1. 在工作流方案中确认任务“待分派”状态的编辑动作位于“更多操作”，保存并刷新项目详情。
2. 进入项目详情“任务”页签，定位待分派任务。
3. 确认操作列不存在固定“编辑”，只显示工作流主操作、“更多”和页面固有删除。
4. 展开“更多”，确认只出现一个“编辑”。
5. 点击“编辑”，确认弹窗标题为“编辑任务”，任务标题、分支、优先级、截止日期和描述来自所选行。
6. 在开发者工具中确认打开弹窗时没有发送工作流 transition 执行请求。

### 场景 B：编辑配置为主操作

1. 将同一编辑动作移动到“主操作”并保存流程图。
2. 刷新项目详情任务页签。
3. 确认操作列直接显示且只显示一个“编辑”，“更多”中不再包含编辑。
4. 点击编辑并确认复用同一个任务编辑弹窗。

### 场景 C：当前状态没有编辑动作

1. 停用编辑动作，或选择一个工作流未返回编辑动作的状态。
2. 刷新任务页签。
3. 确认直接操作和“更多”菜单均不出现编辑。
4. 确认删除等页面固有操作仍按权限显示。

### 场景 D：保存编辑

1. 从工作流编辑入口打开弹窗，修改一个非工作流字段，例如标题或描述。
2. 保存并等待列表刷新。
3. 确认任务字段更新成功，状态、当前处理人和工作流定义未被编辑命令意外改变。
4. 确认网络请求是任务更新接口，不是工作流 transition 执行接口。

## 跨页面回归

- 全局任务列表：“编辑”仍由 `WorkflowActionButtons` 发出命令并打开编辑弹窗。
- 任务详情页：工作流编辑命令仍进入详情编辑模式。
- 项目详情需求页签：不出现固定编辑按钮，工作流编辑继续可用。
- 工作台：需求、任务、Bug 的编辑命令解析保持可用。
- 项目详情 Bug 页签：默认 Bug 工作流没有编辑动作时，固定编辑按钮仍可使用；本次不移除该入口。

## 失败与回滚检查

- 编辑命令处理函数收到未知 `commandType` 时不得打开弹窗或提交请求。
- 工作流动作加载失败时不得回退显示固定任务编辑按钮。
- 编辑保存失败时沿用现有错误提示，弹窗数据不应被错误清空。
- 本次只修改前端入口，不包含数据库迁移或后端回滚步骤。

## 验收证据

验证记录必须包含：

- 聚焦测试、全量测试和构建的完整命令及结果。
- 三种工作流配置下任务操作列截图。
- “更多 → 编辑”打开任务弹窗的截图。
- 网络面板中未调用工作流 transition 接口的证据。
- Bug 固定编辑入口仍可用的审计结果。
