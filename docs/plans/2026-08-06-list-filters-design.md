# 迭代、测试和 Bug 列表筛选设计

## 目标

为迭代、测试管理和 Bug 列表提供与业务字段对应的表格上方筛选，便于定位记录，同时不改变接口、权限或数据加载范围。

## 方案

三个页面继续使用当前的一次性加载与前端分页模型。每页以响应式筛选状态和计算属性从已加载记录得到过滤结果，再将结果交给既有 `usePagination()`；任何筛选变化均将页码重置到第 1 页。

筛选字段固定为：

- 迭代：项目、状态。
- 测试管理：用例库使用关键词和项目；测试单使用关键词和项目。
- Bug：项目、严重程度、状态。

关键词对标题进行不区分大小写的包含匹配；其余字段使用精确匹配。筛选区提供清空按钮。不会新增后端查询参数，因此现有项目可见范围和操作权限保持不变。

## 验证

- 前端源码契约测试覆盖每页限定的筛选字段、过滤数据源和筛选后重置分页。
- 执行新增测试、完整前端测试、生产构建和 `git diff --check`。
