# 迭代负责人权限边界设计

## 目标

为交付迭代的负责人建立独立、受限且可审计的操作权限。迭代负责人只管理交付节奏和范围，不取得项目治理或工作项内容编辑权限。

## 授权模型

- 迭代负责人必须是迭代关联项目的有效成员；项目关闭、负责人被移出所有关联项目或负责人字段变更后，旧负责人立即失去迭代负责人权限。
- 迭代负责人可查看迭代详情、范围、阻断项与审计记录；可编辑名称、目标和计划日期；可执行迭代工作流动作；可纳入、移出和延期迭代范围内的工作项。
- 迭代负责人不得修改项目配置、成员、工作流方案或业务组件；不得以此身份编辑工作项内容、修改工作项处理人或执行工作项流转。
- 系统管理员、项目负责人和上级项目负责人可覆盖迭代负责人操作。覆盖操作必须填写原因，并写入状态操作或迭代审计记录。
- 迭代负责人变更和删除仅允许项目负责人或系统管理员执行。

## 实现边界

后端在项目权限服务中提供独立的迭代负责人判定和操作级校验，迭代控制器针对详情查看、范围管理、生命周期、变更负责人和删除分别调用对应校验。工作流运行时根据对象类型为迭代操作接入该校验，并在治理者覆盖时强制要求原因。

前端从后端返回的迭代详情及当前登录用户推导可见入口，只显示迭代负责人职责范围内的按钮；服务端校验仍是最终授权依据。N-004 至 N-006 仅调整指定 Vue 模板与契约测试，不改变数据或业务规则。

## 验证

后端 API 测试覆盖负责人允许、非成员负责人拒绝、普通成员拒绝、治理者覆盖需原因、负责人变更和删除限制、项目关闭或成员失效后的拒绝。前端源契约测试覆盖三个页面修复及迭代负责人入口；最后执行前后端回归、构建和差异检查。
