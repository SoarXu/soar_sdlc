# 工作项提出人文本化设计

## 目标

将需求和 Bug 的“提出人”从系统用户身份改为可选纯文本。页面可任意输入，需求 Excel 导入原样保存且不校验用户；任务当前没有提出人字段，不新增。

## 数据模型

- `requirements.proposer_id` 替换为 `requirements.proposer`，类型为可空 `TEXT`。
- `bugs.reporter_id` 替换为 `bugs.proposer`，类型为可空 `TEXT`。
- Alembic 迁移先新增文本列，根据旧用户 ID 回填用户全名（无全名时使用用户名），再删除旧 ID 列。
- API 创建、更新和读取统一暴露 `proposer: str | None`，输入去除首尾空白，空字符串按 `None` 保存。

## 界面与导入

- 需求和 Bug 的所有新增、编辑入口将用户下拉框替换为普通文本输入框。
- 详情页直接显示 `proposer`，不再通过用户列表解析。
- Excel 的“提出人”单元格直接写入 `proposer`，不调用用户解析逻辑；任意非空文本都视为有效。
- 从测试用例或测试单生成 Bug 时，若未填写提出人，使用当前执行人/测试人的显示名称作为文本默认值。

## 工作流语义

- 删除 `proposer`、`reporter`、`bug_reporter` 用户身份和处理人来源选项。
- 默认 Bug 流程中删除 `reporter` 权限条件，保留测试人员、项目成员和项目负责人原有权限。
- Bug 验证人选择不再回退到报告人，继续使用来源用例默认测试人和项目默认测试人等规则。
- “我发起的”仅按真实 `creator_id` 判断；提出人文本只用于业务展示。
- 审计历史将 `proposer` 当作普通文本显示，不再按用户 ID 翻译。

## 兼容与验证

- 测试环境仍执行数据回填，保证现有测试数据可读。
- 后端测试覆盖模型/API、任意提出人导入、工作台和工作流身份移除。
- 前端源代码契约测试覆盖所有输入框、字段名和详情展示入口。
- 运行后端相关测试、前端测试和前端生产构建，并用全仓搜索确认生产代码不再引用 `proposer_id`/`reporter_id`。

## Git 约束

所有变更仅保留在本地工作区，除非主上后续明确选择提交、推送、创建 PR 或合并。
