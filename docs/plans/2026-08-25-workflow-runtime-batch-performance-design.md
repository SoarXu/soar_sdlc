# 工作台与项目页面批量加载性能优化设计

## 背景

工作台、项目集和项目列表都会调用 `POST /api/v1/workflow-runtime/transitions/batch` 加载当前用户可见的工作流动作。该接口虽然使用批量协议，内部仍逐项调用单对象查询；每个对象又重复执行默认工作流模板协调、权限、角色、成员和组件路由查询。当前数据下，28 个项目产生 4,363 条 SQL，15 条工作台数据产生 2,648 条 SQL。

项目集和项目列表还会为每个项目分别调用成员接口，形成额外的 HTTP N+1。

## 目标

- 保持现有批量工作流接口的请求和响应协议。
- 默认工作流模板在一次批量请求中只协调一次。
- 批量加载对象、状态、流转和共享权限数据，避免逐对象重复查询。
- 用一个批量成员请求替代逐项目成员请求。
- 保持现有权限、动作顺序、表单配置和页面交互不变。
- 为批量接口建立查询数量回归上限，并记录慢请求的 SQL 数量和数据库耗时。

## 方案

### 工作流批量上下文

批量入口先调用一次 `ensure_default_workflow_templates()`，再按对象类型分组加载工作项。收集工作流定义、当前状态和候选流转后，以请求级上下文预取并缓存以下共享数据：

- 当前用户的系统管理员状态和角色；
- 流转允许角色、目标角色和回退角色；
- 涉及项目及项目成员；
- 工作项关联的业务组件、组件成员和组件路由；
- 候选目标状态和 Bug 类型选项。

单项动作解析继续复用现有规则，但读取请求级上下文。未覆盖的复杂分支允许回退到现有查询逻辑，确保权限语义优先于查询上限。

### 默认模板协调

`list_available_transitions()` 保持单对象调用时的自包含行为。新增内部参数或内部实现入口，使批量调用能够跳过逐项模板协调；批量入口负责在循环前协调一次。不得在批量循环内提交事务。

### 项目成员批量接口

新增项目成员批量读取接口，输入项目 ID 列表，返回以项目 ID 分组的成员数据。权限规则与现有单项目接口一致。项目集和项目列表改为一次请求，现有单项目接口继续保留。

### 前端加载范围

项目列表只为当前分页可见的项目树分支请求工作流动作；分页或数据刷新时替换动作映射。项目集当前展示完整树，因此动作仍覆盖当前展示树，但只产生一个成员请求和一个动作请求。

### 数据库可观测性

在请求范围统计 SQL 数量与数据库执行耗时，仅当 API 请求超过慢请求阈值时记录结构化警告。日志不得包含 SQL 参数、认证信息或业务正文。现有 MySQL `pool_pre_ping` 和 `pool_recycle` 保持不变，避免在没有连接池耗尽证据时调整容量。

## 错误处理

- 批量请求包含不存在对象时，保持现有单项错误语义，不静默丢弃。
- 批量成员接口对不可见项目执行与现有成员接口一致的权限校验。
- 前端成员批量加载失败时维持空成员映射并显示现有错误提示，不阻塞基础列表展示。

## 测试

- 后端行为测试比较批量与逐项动作结果，覆盖项目、需求、任务和 Bug。
- 查询计数测试证明增加对象数量不会按当前倍数增长，并禁止每项重复模板协调。
- 批量成员接口覆盖分组、空输入和权限边界。
- 前端契约测试验证项目页面不再循环调用成员接口，并只为当前页加载动作。
- 运行工作流、工作台、项目权限相关回归测试和前端生产构建。
