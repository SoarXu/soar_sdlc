# 问题收集集中处理设计

## 目标

解决 `issue.md` 中记录的界面一致性、项目生命周期、工作台覆盖范围和工作流方案数据完整性问题。

## 设计决策

### 操作列

项目列表和项目集树使用同一套工作流操作按钮样式。项目的启动、暂停和关闭均直接显示在操作列；其他低频动作仍归入“更多”。操作按钮与删除按钮采用相同的尺寸、行高和间距。

### 项目生命周期权限

项目生命周期属于项目管理动作，不属于工作项代处理。项目负责人、项目集继承负责人和系统管理员执行项目的启动、暂停、关闭、激活时，不生成也不要求 `delegate_reason`。需求、任务和 Bug 的代处理审计规则不变。

### 工作流术语

项目列表列名由“工作流方案”调整为“分派规则方案”。未绑定自定义方案时显示“默认系统工作流”，但不改变系统默认项目、需求、任务和 Bug 工作流的现有回退机制。

### 工作台

在现有工作台查询和视图模型中纳入任务和 Bug。它们遵循与需求一致的项目范围、当前处理人、创建人、关注、提及和异常中心规则，并复用工作流动作与跳转逻辑。

### 重复 Bug 工作流定义

方案 `1` 保留默认 Bug 工作流定义（ID `33`），停用调试定义 `debug-def`（ID `466`）。同时增加服务端约束与管理侧校验，确保每个分派规则方案每种对象类型最多只有一条启用工作流；遇到历史冲突时返回包含冲突定义信息的中文错误。

## 范围外

- 不改变需求、任务、Bug 的代处理审计规则。
- 不改变项目成员、工作流配置和其他工作项权限。
- 不删除历史工作流定义，仅停用重复定义。

## 验证

- 覆盖项目生命周期不再要求代处理原因，且工作项代处理仍要求原因。
- 覆盖项目和项目集列表的暂停、关闭直出和统一按钮样式。
- 覆盖工作台中任务、Bug 的待处理、我发起和范围过滤。
- 覆盖重复 Bug 定义的修复、创建 Bug 成功和新增重复定义拒绝。
