# 后续问题清单

## 使用范围

本文件用于登记 SOAR SDLC 平台后续发现、尚未解决的问题。每个问题必须先完成复现和影响确认，再建立对应的中文执行计划；未经验证不得标记为已解决。

## 问题状态

- 待确认：已收到现象，尚未稳定复现或确认影响。
- 待计划：已确认问题，等待制定执行计划。
- 待实施：计划已确认，等待集中处理。
- 实施中：正在修复或补充自动化测试。
- 待验证：实现已完成，等待回归与验收。
- 已解决：验证通过，保留问题、计划和验证证据。

### N-001 迭代生命周期动作收进更多菜单

- 状态：已解决
- 类型：体验问题
- 优先级：P2
- 发现时间：2026-08-05
- 影响范围：迭代详情页、迭代列表，以及项目详情页的迭代操作列。
- 复现步骤与证据：创建或打开处于“规划中”的迭代；在上述任一入口中查看操作区，“开始”显示在“更多”下拉菜单内。迭代进入“进行中”后，“完成”和“取消”同样受该菜单分组影响。
- 预期结果：迭代在任一入口中只要存在当前可执行的生命周期动作（开始、完成或取消），均直接显示为操作按钮，不显示“更多”菜单。
- 实际结果：通用工作流动作组件未按详情或迭代对象区分分组；迭代动作遵循默认的“更多操作”分组，导致生命周期动作被收进下拉菜单。
- 根因分析：`WorkflowActionButtons.vue` 对所有模式调用 `splitListActions()`；该函数仅对项目对象的少数动作设为直显，迭代对象仍完全依赖 `list_display` 配置。默认迭代动作未配置为主操作。
- 执行计划：`docs/plans/2026-08-05-iteration-actions-direct-display.md`
- 验证结果：`node src/utils/workflowRuntimeActions.test.mjs`、前端 `npm test`（12/12）及 `npm run build` 均通过；迭代动作及自定义迭代动作均进入直显操作，`moreActions` 为空。

### N-004 启动迭代未同步启动关联项目及项目集

- 发现时间：2026-08-05
- 影响范围：交付迭代的生命周期、关联项目及其所属项目集树。
- 复现步骤与证据：在项目和项目集均为“规划中”时，启动关联该项目的交付迭代；迭代已进入“进行中”并记录实际开始日期，但项目和项目集仍显示“规划中”。截图中的“20260804-项目一”及其项目集“20260804”即为该状态组合。
- 预期结果：启动迭代时，系统在同一事务内启动仍处于规划中的关联项目，并同步启动这些项目所属的项目集及其祖先；任一关联项目或项目集已关闭时，拒绝启动迭代且不产生部分状态变更。
- 实际结果：通用工作流运行时仅校验迭代不是需求池并更新迭代自身状态和实际开始日期，未校验或同步关联项目、项目集状态。

- 验证结果：`pytest backend/tests/test_iteration_detail_api.py -q` 通过（32 passed）；覆盖关联项目及项目集祖先同步、多项目、已进行中项目保持不变并回填项目集开始日期、关闭父级拒绝且无部分更新。

### N-005 需求关联迭代后，关联任务未同步迭代归属

- 状态：已解决
- 类型：数据问题
- 优先级：P1
- 发现时间：2026-08-05
- 影响范围：需求创建任务、迭代关联或解绑需求、需求延期，以及迭代结束的未完成事项校验。
- 复现步骤与证据：在 QA档案管理的迭代 1 中，4 个需求子任务均关联到需求，但任务自身的 `iteration_id` 为空；结束迭代弹窗只按任务自身的 `iteration_id` 统计，因此仅显示直接关联迭代的任务，遗漏需求子任务。
- 预期结果：任务关联需求时，任务与需求保持相同的迭代归属；需求绑定、解绑或延期时，关联任务同步更新。结束迭代时，未完成的需求子任务应出现在任务阻断明细中。
- 实际结果：普通任务创建、需求关联迭代、需求解绑和需求延期路径均未同步关联任务的 `iteration_id`；此前测试还固化了“需求子任务不阻断结束迭代”的旧口径。
- 根因分析：任务创建服务仅使用请求中的 `iteration_id`；迭代服务移动需求时只调用需求自身的迭代归属操作，未遍历 `requirement_id` 对应的任务。结束迭代校验只查询直接归属迭代的任务，导致不一致数据被遗漏。
- 执行计划：`docs/plans/2026-08-05-requirement-task-iteration-sync.md`
- 验证结果：5 项后端核心回归通过，覆盖普通任务创建继承、需求绑定与解绑同步、需求延期同步、结束迭代阻断需求子任务和既有的需求生成任务继承路径；前端 `npm test` 通过，`git diff --check` 通过。

- 发现时间：2026-08-05
- 影响范围：工作台及详情页中需求、任务的“重新激活”动作。
- 复现步骤与证据：为“重新激活”工作流动作配置可执行角色及手动选择处理人权限；由已获该动作权限、但不是项目管理员的用户重新激活并选择下一处理人，系统提示“Only project administrators can select a reactivation handler”。

### N-015 已停止项目的历史 Bug 无法转入维护项目组件处理

- 验证结果：新增跨项目维护组件激活端到端回归；`pytest backend/tests/test_bug_workflow_api.py -q` 通过（17 passed），覆盖维护组件选项、项目/组件/迭代迁移和源/目标项目审计。

### N-016 用户可见错误提示存在英文且响应结构不统一
