# 系统模板流程图同步设计

## 背景

“套用模板”当前从代码内置的 `graph_for_object_type()` 读取图，而不是从数据库中的系统标准方案读取。因此，管理员修改后的默认工作流规则不会成为系统模板的初始内容，状态坐标与连线路由也会被代码中的旧坐标覆盖。需求工作流的内置图甚至将“处理中”和“待确认”放在同一坐标，导致节点重叠。

## 已确认规则

- “默认工作流规则”和“系统标准方案”是两套独立维护的工作流。
- 仅在本次发布时，把当前“默认工作流规则”的需求、任务、Bug、项目工作流复制到对应系统模板。
- 之后编辑默认工作流规则不自动更新系统模板，编辑系统模板也不回写默认工作流规则。
- “套用模板”始终读取持久化系统模板，而不是代码静态图或默认工作流规则。
- 同步与套用均保留状态、流转、节点位置、连线路由和全部有效配置。

## 数据流

```text
默认工作流规则（一次性迁移源）
  -> 对应系统模板（独立持久化来源）
  -> 管理员点击“套用模板”时的预览
  -> 目标工作流保存
```

默认工作流规则由名称“默认工作流规则”定位；系统模板由 `scope_type='system'`、`is_default_template=true` 和对象类型定位。同步范围为需求、任务、Bug、项目；迭代系统模板没有对应默认规则来源，不纳入本次同步。

## 同步策略

系统模板中存在历史工作项状态引用，不能删图重建。同步服务以稳定 `state_role` 优先、`(status_name, category)` 其次、`(分类、终态类型、排序)` 最后匹配源与目标状态，且只复用唯一候选；原地更新状态的业务属性和 `x/y`，从而保留可识别目标状态 ID。默认规则新增的状态会在系统模板中创建；来源已删除且未再匹配的历史状态会停用保留。

流转按动作键和映射后的来源状态分组，同组先按映射后的目标状态匹配；同目标的历史重复动作再按“启用优先、排序、ID”稳定配对，允许本次同步修正目标状态。无法匹配的来源流转会新建，系统模板中来源已删除的流转会停用保留。已配对流转原地更新动作名称、权限、处理人规则、条件、校验、后置动作、UI、表单、连线路由、启停与排序，并替换角色引用。

这使默认规则在管理员修改状态、流转或图形后仍能完成一次迁移，同时不删除可能被历史工作项、组件路由或审计记录引用的系统记录。同步只匹配唯一候选，不对含糊的非稳定身份做猜测性复用。

## 套用策略

模板预览和直接套用接口从同对象类型的持久化系统模板构造目标图。源状态 ID 映射为目标工作流的状态 ID；状态角色尚未回填的历史节点可按同名及分类复用。流转按动作键、来源状态和目标状态复用已有 ID，避免重复套用模板后产生新的停用虚线边；流转中的条件路由和处理人目标状态同步重映射。状态坐标与 `diagram_config` 原样复制，并规范化历史 `ui_config.list_priority` 字段；前端只展示预览并保存，不执行自动布局。

迁移仅在缺少系统模板时创建基础记录，且不对既有默认规则或系统模板执行启动期修复；全程由 Alembic 的单一事务提交或回滚，保证管理员看到的当前默认图是本次复制源。

图复制不会保留 `parent_definition_id`。复制结果没有运行时依赖于来源定义，满足系统标准方案、默认工作流规则及后续方案副本各自独立维护的约束。

## 验证

- 一次性迁移后，四个系统模板与默认工作流规则在忽略定义与记录 ID 后完整一致。
- 已引用系统状态的记录仍指向原状态 ID。
- 系统模板自定义位置与路由可由预览和直接套用完整复制到目标图。
- 默认工作流规则在迁移后编辑，不会改变系统模板。
- 模板源缺失或图语义不一致时，迁移显式失败而不部分写入。
