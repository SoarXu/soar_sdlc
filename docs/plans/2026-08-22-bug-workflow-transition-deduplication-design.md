# 缺陷工作流确认动作去重设计

## 目标

修复已部署缺陷流程图中重复启用“确认缺陷类型”流转导致的保存失败，同时保持工作流保存接口对同一来源状态同名启用动作的校验，不把数据异常转化为运行时歧义。

## 现状与边界

N-004 将“确认缺陷类型”迁移到 N-002 定义的 `active_work` 状态角色。部分已部署定义在该迁移路径中同时保留了原动作并新增了同键、同名、同源、同目标的启用动作。保存图接口已正确拒绝这种重复，但读取和运行时协调没有修复历史数据。

本项仅处理系统默认缺陷工作流及可证明由默认图派生的系统管理方案。管理员自定义流程图不按名称或动作键推测和修改，避免覆盖其业务配置。

## 规范化规则

对每个系统管理的缺陷定义，`active_work` 状态下 `action_key=confirm_bug_type` 必须只保留一条启用流转：

1. 按流转 ID 升序选择最早记录为规范记录。
2. 使用既有 `_bug_confirmation_transition()` 模板校正规范记录的动作名称、路由、表单、权限、展示与启用配置。
3. 将其余同键且同来源状态的记录停用，并清除 `auto_disabled_by_state` 标记；它们不再被运行时或保存校验视为启用动作，流程图仍按既有停用流转规则展示为虚线。
4. 协调再次执行时不再变更任何记录，也不再增加版本号。

停用而不是物理删除重复记录，以保留历史配置、避免破坏可能存在的外部流转 ID 引用，并符合已确定的停用流转可视化语义。

## 数据修复与运行时防线

新增 Alembic 数据迁移，在 N-005/N-006 的既有迁移链之后调用同一幂等协调函数，修复已部署数据库。服务启动和读取默认工作流时也会调用同一协调函数，因此尚未执行迁移的本地开发环境在刷新工作流图后同样会被规范化。

保存接口的唯一性校验保持不变。它仍是管理员手工配置产生重复动作时的最后一道防线；本修复只确保系统管理的历史图不会以异常数据进入该边界。

## 验证

自动化测试构造两条位于 `active_work` 的同键、同名启用确认动作，验证首次协调后只剩一条启用记录、规范记录配置正确、额外记录停用；第二次协调必须无变化。迁移测试验证修复迁移依赖当前唯一 head 并调用同一协调服务。最后通过工作流定义 API 保存修复后的图，确认不再返回 422。
