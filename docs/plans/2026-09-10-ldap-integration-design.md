# LDAP/AD 集成设计

## 目标

在后台管理中提供 LDAP/AD 集成能力。管理员配置目录服务后，可查询 AD 域员工，选择员工同步到 SDLC 用户列表。被同步用户使用 AD 域账号和密码登录，SDLC 不保存其 AD 密码。

第一期以 Microsoft Active Directory 为默认模板，同时保留属性映射配置以兼容标准 LDAP。

## 核心原则

- 只有已同步且启用的 LDAP 用户可以登录 SDLC。
- LDAP 用户密码仅用于实时向 AD 验证，不进入数据库、日志或缓存。
- 现有用户默认保留为本地用户，账号、权限、项目关系和历史记录不变。
- 保留至少一个本地系统管理员，作为 LDAP 故障时的应急入口。
- 首次导入由管理员手动选择；自动任务只更新已同步用户，不自动新增员工。
- AD 中禁用、删除或移出查询范围的用户在 SDLC 中禁用，但不物理删除。

## 页面结构

LDAP 集成页面采用左右布局：左侧为连接和查询配置，右侧为 AD 域用户列表。窄屏下改为上下布局。

### 左侧：LDAP 配置

#### 连接设置

- 启用 LDAP
- 协议：LDAP 或 LDAPS，推荐 LDAPS
- 服务器地址
- 端口：LDAP 默认 389，LDAPS 默认 636
- 连接超时，默认 5 秒
- Base DN

#### 查询账号

- 绑定账号：兼容完整 DN 和 AD UPN 格式
- 绑定密码：后端加密保存，前端不回显；编辑时留空表示保持原值
- 测试连接：验证网络、证书、绑定凭据和基础查询权限

#### 用户查询

- 用户 Base DN：默认继承 Base DN，可限制到员工 OU
- 用户筛选器：AD 默认 `(&(objectCategory=person)(objectClass=user))`
- 排除禁用账号：默认开启
- 查询分页大小：默认 50

#### 字段映射

| SDLC 字段 | AD 默认属性 |
| --- | --- |
| 用户名 | `sAMAccountName` |
| 工号 | `employeeID` |
| 姓名 | `displayName` |
| 邮箱 | `mail` |
| 手机号 | `mobile` |
| 部门 | `department` |
| 唯一标识 | `objectGUID` |

### 右侧：AD 域用户

LDAP 配置未保存或连接测试失败时显示引导空状态。连接成功后，管理员主动查询或刷新域用户。

列表支持姓名、账号、工号关键词搜索、分页、多选和刷新。显示姓名、AD 账号、工号、部门、邮箱、SDLC 匹配用户与同步状态。

同步状态包括：

- 未同步：SDLC 中没有匹配用户。
- 可绑定：工号、账号或邮箱可能匹配一个现有用户，等待管理员确认。
- 已同步：已通过 LDAP 唯一标识绑定。
- 冲突：匹配到多个用户或关键字段冲突，禁止自动同步。
- AD 已禁用：不可新同步；已同步用户将在同步时被禁用。

管理员选择用户后执行“同步所选用户”。未匹配用户创建为 LDAP 用户；可匹配用户需确认绑定；已同步用户更新资料；冲突项跳过并显示原因。批量操作返回逐项结果和成功、失败统计。

## 用户数据模型

现有用户增加以下字段：

- `employee_no`：工号，允许为空；有效用户中非空值唯一。
- `auth_source`：认证来源，值为 `local` 或 `ldap`；现有用户迁移为 `local`。
- `ldap_external_id`：目录唯一标识，AD 使用 `objectGUID`；LDAP 用户中唯一。
- `ldap_dn`：用户当前 DN，用于认证并可在同步时更新。
- `ldap_last_synced_at`：最近同步时间。

工号用于首次匹配和人工确认，不作为长期绑定主键。绑定完成后使用 `ldap_external_id` 识别用户，避免用户名、工号或 OU 变化造成重复用户。

现有用户的工号由管理员在用户管理页面逐个补录。用户列表在账号与部门之间增加工号列，新增和编辑用户表单增加工号字段。

## 匹配与绑定规则

匹配优先级如下：

1. `ldap_external_id` 相同：直接识别为已绑定用户。
2. 工号唯一匹配：建议绑定，必须由管理员确认。
3. 用户名或邮箱唯一匹配：提示可能匹配，必须由管理员确认。
4. 多项命中不同用户、字段重复或信息冲突：阻止同步，人工处理。
5. 无匹配：创建新的 LDAP 用户。

绑定现有用户时保留原用户 ID、角色、项目成员关系、工作项关系和历史记录。绑定完成后切换为 LDAP 认证，本地密码不再用于登录。系统管理员可继续保留本地认证。

## 登录流程

1. 用户提交账号和密码。
2. SDLC 查询本地启用用户；不存在或未同步时返回统一的账号密码错误。
3. `local` 用户沿用本地密码校验。
4. `ldap` 用户使用保存的 DN 和本次输入的密码向 AD 执行绑定认证。
5. AD 验证成功后，SDLC 签发自身访问令牌，现有授权逻辑保持不变。

LDAP 用户不显示重置密码和首次改密功能。AD 认证失败不降级到本地密码。账号不存在和密码错误使用统一提示，避免账号枚举。

## 自动同步

- 每周日凌晨 2 点同步已绑定 LDAP 用户。
- 管理员可随时手动同步已绑定用户。
- 自动同步只更新已绑定用户，不导入其他 AD 员工。
- 更新姓名、用户名、工号、邮箱、手机号、部门、DN 和启用状态。
- 单个用户失败不终止整个批次。
- 保存执行时间、操作来源、成功数、失败数和逐项错误摘要。

LDAP 用户在每次登录时实时接受 AD 认证，因此 AD 禁用后无法再次登录。为限制已登录会话的风险，LDAP 用户访问令牌有效期建议不超过 8 小时。

## 安全与异常处理

- 绑定密码使用应用密钥加密后存储，API 永不返回明文或密文。
- 推荐 LDAPS，并验证服务器证书；不提供生产环境跳过证书验证的开关。
- 对连接、查询、认证设置明确超时。
- 日志不得记录绑定密码、用户密码或完整认证载荷。
- LDAP 不可用时，LDAP 用户提示“目录服务暂时不可用”，本地管理员仍可登录。
- 配置保存与测试连接分离；启用 LDAP 前必须完成成功的连接测试。
- 同步失败保留 SDLC 当前数据，不因临时查询失败批量禁用用户。
- 仅在成功完成完整同步并明确确认 AD 状态后执行用户禁用。

## 测试范围

- 配置保存、密码留空更新、加密存储和敏感字段脱敏。
- LDAP/LDAPS 连接、证书失败、超时、凭据错误和查询权限不足。
- AD 用户搜索、分页、属性缺失、禁用账号和大目录查询。
- 新建、匹配、确认绑定、冲突、重复工号和重复唯一标识。
- 本地用户登录、LDAP 用户登录、未同步用户拒绝、AD 禁用用户拒绝。
- 自动同步仅更新已绑定用户，部分失败不影响其他用户。
- LDAP 故障时本地管理员可登录，LDAP 用户不降级认证。
- 现有用户迁移后 ID、角色、项目关系和历史引用保持不变。
