# 进行中迭代单表工作台设计

## 目标

将工作台改为一张可筛选的工作项表，默认显示当前用户有权限查看、归属进行中迭代的全部需求、任务和 Bug。已完成或已取消的工作项仍在默认集合内，但排序权重低于未结束项。

## 数据范围

后端以项目可见性为边界，收集工作流状态分类为 `in_progress` 的迭代，再读取其中未删除的需求、任务和 Bug。接口返回一个去重后的标准集合，保留类型、项目、迭代、状态、优先级、负责人、当前处理人、截止日期、更新时间和逾期信息。旧的待办、关注、提及和异常队列可继续保留为兼容数据，但不再驱动主列表。

## 界面与筛选

移除工作台的来源切换和嵌套关注标签页。单表上方提供关键词、项目、迭代、类型、状态、优先级、负责人和当前处理人的组合筛选；默认不设置筛选值。保留详情跳转、工作流操作和既有同项目同类型批量指派限制。

## 默认排序

排序顺序为：未结束工作项优先，逾期项优先，优先级从高到低，截止日期从近到远，最后按更新时间从新到旧。无截止日期排在有截止日期之后；完成和取消状态继续可见，但排在未结束项之后。

## 验证

后端测试验证权限边界、进行中迭代范围和三类工作项的完整性。前端测试验证不再使用来源切换、筛选字段完整以及默认排序。实现时保持现有操作命令和批量选择约束不变。
