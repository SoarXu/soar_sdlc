# 工作项状态矩阵设计

## 目标

需求、任务和 Bug 的状态必须同时反映处理人和所属迭代阶段，而不是永远使用工作流初始状态。状态名称仍由工作流管理员维护，但系统决策只依赖不可随名称变化的状态角色。

## 状态角色

在 `workflow_states` 新增可空的 `state_role`，同一工作流定义内每种角色最多一个。N-002 使用以下角色：

| 角色 | 默认需求/任务状态 | 默认 Bug 状态 | 语义 |
| --- | --- | --- | --- |
| `unassigned` | 待分派 | 待分派 | 没有处理人，不能开始实际工作。 |
| `waiting_iteration` | 待开始 | 待开始 | 已有处理人，但迭代尚未开始。 |
| `active_work` | 处理中 | 修复中 | 已有处理人，且迭代正在进行。 |

其余评审、验证和终态不设置这三个角色。角色可为空，以兼容不参加本状态矩阵的历史自定义状态；运行时不会根据 `status_name` 推断角色。

## 状态矩阵

| 场景 | 无处理人 | 有处理人 |
| --- | --- | --- |
| 在未开始迭代创建 | `unassigned` | `waiting_iteration` |
| 在进行中迭代创建 | `unassigned` | `active_work` |
| 在未开始迭代认领或指派 | 不适用 | `waiting_iteration` |
| 在进行中迭代认领或指派 | 不适用 | `active_work` |
| 取消指派 | `unassigned` | 不适用 |
| 迭代从未开始变为进行中 | 保持 `unassigned` | `waiting_iteration` 自动流转至 `active_work` |
| `waiting_iteration` 移入进行中迭代 | 不适用 | 自动流转至 `active_work` |
| `active_work` 移入未开始迭代 | 阻断 | 阻断 |

工作项创建本身不补写状态操作记录。迭代启动和移动触发的状态变化必须使用隐藏的系统流转，并写入正式状态操作历史，便于审计。

## 工作流与迁移

默认需求、任务和 Bug 工作流均配置上述角色。需求和任务新增“待开始”节点；Bug 将原“待处理”迁移为“待分派”并新增“待开始”。

“认领”“指派”使用迭代阶段路由，在同一流转内选择 `waiting_iteration` 或 `active_work`；“取消指派”从已分派角色返回 `unassigned`。从 `waiting_iteration` 到 `active_work` 的“迭代启动”流转是系统动作，不能由用户手工触发或显示为操作按钮。

迁移只对具有可识别旧图结构的需求、任务和 Bug 工作流执行：通过既有动作键、状态类别和唯一默认状态组合回填角色、增加等待节点并重接相关流转。无法无歧义识别的自定义图不按中文名称猜测；管理员需要在工作流状态配置中设置角色后才能使用该矩阵。

## 运行时边界

状态角色解析集中在工作流状态服务中。创建服务传入 `owner_id` 与 `iteration_id`，得到适用工作流、初始状态和角色。工作流运行时负责：

- 对指派、认领、取消指派按角色和迭代阶段解析目标状态；
- 在迭代状态已切换为进行中后批量执行符合条件的隐藏“迭代启动”流转；
- 在工作项移动时检查禁止方向，或对等待状态执行同一隐藏流转；
- 对缺少角色、角色重复、系统流转缺失返回结构化冲突信息并回滚事务。

默认模板更新、新创建方案和已迁移方案均使用相同的角色契约；运行时不读取状态中文名称。

## 前端

工作流状态抽屉在需求、任务和 Bug 图中提供“系统状态角色”选择器。默认状态模板展示角色值；其他工作流类型不显示该配置。前端只保存角色字段，后端负责唯一性、完整性和运行时状态选择。

工作项列表、详情和流程按钮继续读取服务端返回的 `status_name` 与可用流转，因此状态变更后自然显示“处理中”或“修复中”及其对应按钮，不新增前端状态判断分支。

## 风险与约束

- 角色不是历史 `status_key` 的恢复，也不用于展示；它是受控的系统语义字段。
- 迁移必须可重入，不能重复插入等待状态或重复创建系统流转。
- 迭代启动、需求带动关联工作项迁移和任务树移动会共享同一状态联动服务，后续 N-005 直接复用。
- Bug 的动作集合调整留给依赖 N-002 的 N-004；本项只建立状态角色和阶段路由基础。
