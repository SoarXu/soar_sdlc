# 后续问题清单

## 使用范围

本文档用于登记 SOAR SDLC 平台后续发现、尚未解决的问题。每一个问题必须先完成复现和影响确认，再建立对应的中文执行计划；未经验证不得标记为已解决。

## 问题状态

- 待确认：已收到现象，尚未稳定复现或确认影响。
- 待计划：已确认问题，等待制定执行计划。
- 待实施：计划已确认，等待集中处理。
- 实施中：正在修复或补充自动化测试。
- 待验证：实现已完成，等待回归与验收。
- 已解决：验证通过，保留问题、计划和验证证据。

### N-001 创建项目默认生成迭代，且需求创建缺少可用迭代约束

- 状态：已解决
- 类型：功能与数据一致性问题
- 优先级：P2
- 发现时间：2026-08-18
- 影响范围：项目创建、项目迭代列表，以及需求创建入口。
- 复现步骤与证据：创建项目后进入项目详情的“迭代”页。截图显示项目“小样纯化”存在系统生成的“待规划迭代”，状态为“规划中”。
- 预期结果：创建项目时不自动创建任何迭代。创建需求时，必须关联该项目中状态为“规划中”或“进行中”的迭代；当不存在此类迭代时，禁止创建需求并提示用户先创建可用迭代。
- 实际结果：项目创建后存在“待规划迭代”。
- 根因分析：`project_service.create_project()` 在项目工作流初始化后无条件调用 `create_unstarted_iteration()`，因此每个新项目都会创建“待规划迭代”。
- 执行计划：移除项目创建流程中的自动迭代创建；保留需求 API 的迭代必填和状态范围校验，以及前端需求表单对可用迭代的筛选和必填校验。
- 验证结果：新增项目创建零迭代回归测试，先确认旧实现失败，再移除自动创建调用后通过。后端定向 `python -m pytest tests/test_requirement_real_iteration_assignment_api.py::test_project_creation_does_not_provision_a_default_iteration tests/test_requirement_real_iteration_assignment_api.py::test_requirement_create_requires_explicit_iteration tests/test_requirement_real_iteration_assignment_api.py::test_requirement_create_accepts_only_eligible_project_scoped_iteration -q` 通过（4 passed），覆盖新项目无迭代、需求缺少迭代拒绝、项目范围外或已关闭迭代拒绝、规划中和进行中迭代接受；`python -m compileall -q app/services/project_service.py app/services/requirement_service.py app/services/iteration_assignment_service.py` 通过。前端 `node src/views/requirementRealIterationAssignment.test.mjs` 通过，生产构建 `npm run build` 通过（1779 modules transformed）；验证未创建测试用户。

### N-003 测试用例富文本输入框默认高度过大且占位提示未中文化

- 状态：已解决
- 类型：功能与体验问题
- 优先级：P2
- 发现时间：2026-08-18
- 影响范围：测试用例新增和编辑弹窗中的前置条件、用例步骤、预期结果输入框。
- 复现步骤与证据：进入项目详情“测试”页，点击“新增用例”。截图显示前置条件、用例步骤、预期结果三个空白富文本输入框均以较大固定高度展开，且占位提示为英文“Paste text or screenshots here”。
- 预期结果：三个输入框在为空或内容较少时以紧凑的单行或内容最小高度展示，并随输入文本或粘贴内容的实际高度自适应增长，便于在同一页面查看表单；保留文本格式和截图粘贴能力。占位提示统一使用中文“可粘贴文本或截图”。
- 实际结果：三个输入框打开即以较大固定高度展示，压缩弹窗中其他字段的可视区域；占位提示仍为英文。
- 根因分析：通用 `RichTextPasteEditor` 的默认占位提示为英文，样式为 `min-height: 150px`，导致所有空白编辑区以较大固定最小高度打开。
- 执行计划：将通用组件默认占位提示改为中文；把编辑区最小高度收紧为 44px，不设置固定高度以使内容自然增长，保留 320px 最大高度和内部滚动以约束长内容。
- 验证结果：新增展示契约测试，先因英文占位提示失败；实现后 `node src/components/richTextPasteEditorPresentation.test.mjs`、`node src/utils/richTextEditorModel.test.mjs` 和 `node src/utils/clipboardHtml.test.mjs` 均通过，覆盖中文默认提示、44px 最小高度、320px 长内容约束、DOM 同步清洗和截图粘贴清洗。`npm run build` 通过（1779 modules transformed）；未创建测试用户。

### N-004 测试用例适用范围仅支持单选

- 状态：已解决
- 类型：功能与体验问题
- 优先级：P2
- 发现时间：2026-08-18
- 影响范围：测试用例新增和编辑弹窗、测试用例详情与列表展示、适用范围筛选，以及测试用例数据存储接口。
- 复现步骤与证据：进入项目详情“测试”页并点击“新增用例”，打开“适用范围”下拉框。截图显示该控件一次只能选择一个测试环节，选项包括单元测试环节、功能测试环节、集成测试环节、系统测试环节、冒烟测试环节、版本验证环节。
- 预期结果：适用范围支持多选，使同一测试用例可关联多个测试环节。保存后以范围列表存储，详情和列表以多个标签展示，筛选时按任一已选范围命中；既有单选数据兼容转换为仅含原值的范围列表。

### N-005 修改工作流连线目标状态时报“无效图形配置”

- 状态：已解决
- 类型：功能与体验问题
- 优先级：P2
- 发现时间：2026-08-18
- 影响范围：工作流设计器中已有连线的编辑、工作流模板保存。
- 复现步骤与证据：在缺陷工作流中，将“验证不通过”连线的目标状态改为“修复中”，保存时提示“无效图形配置”。
- 预期结果：修改连线目标状态后，系统应自动更新与新端点匹配的图形路由；如原路由为用户手工绘制且无法复用，应给出可理解的提示并允许重置或重新绘制，而不是以技术错误阻止保存。
- 实际结果：仅修改连线目标状态即保存失败，前端只展示“无效图形配置”，用户无法判断需要处理的配置内容。
- 根因分析：连线的 `to_state_id` 已更新，但原有 `diagram_config` 仍按旧起止节点保存。该陈旧路由与新端点不一致，后端图形配置校验拒绝保存并返回技术性错误。
- 执行计划：前端在变更连线端点时重算或清除自动路由；对于手工路由，提示用户重置或重绘。后端识别陈旧的自动路由并安全重算，或返回包含可操作处理方式的错误信息。
- 验证结果：先新增自动布线路径在变更目标状态后再次保存的回归测试，旧实现返回“无效图形配置”；实现后 `python -m pytest tests/test_workflow_definition_api.py::test_save_graph_clears_stale_generated_route_after_transition_target_changes tests/test_workflow_definition_api.py::test_save_graph_round_trips_transition_diagram_config tests/test_workflow_definition_api.py::test_save_graph_rejects_invalid_transition_diagram_config -q` 通过（11 passed）。前端 `node src/utils/workflowManualRoute.test.mjs`、`node src/components/workflowDesignerDrawerIntegration.test.mjs` 和 `node src/components/workflowAdvancedConfigDrawer.test.mjs` 均通过，覆盖变更端点清除旧路径、手工路径确认和组件事件接线。手工路径异常提示更新为“图形路径无效，请恢复自动布线或重新绘制路径”。
