# 工作流状态与流转启停联动设计

## 背景

工作流状态配置当前提供“删除状态”按钮，但前端会阻止删除任何仍有关联流转的状态。既有流转在后端只能停用，不能从图保存载荷中删除，因此用户无法通过界面满足删除前置条件。

状态也可以通过“启用”开关停用，但关联流转不会同步停用。这样可能保留指向不可用状态的启用流转，运行时一旦暴露或执行该流转，就会进入没有可用状态语义的不一致数据。简单地在状态恢复时启用全部关联流转又会误恢复原本由用户手工停用的流转。

## 目标

- 移除状态配置中的“删除状态”按钮，以启用开关作为状态退出使用的唯一入口。
- 状态停用时自动停用关联流转，同时继续在流程图中以灰色虚线展示。
- 状态恢复时只恢复此前因状态停用而自动停用的流转。
- 在前端提供即时反馈，并由后端保存边界保证最终数据一致性。
- 保留既有状态、流转和业务操作历史，不引入物理删除行为。

## 非目标

- 不新增状态或流转的物理删除接口。
- 不清理数据库中既有的重复或停用流转。
- 不改变工作流运行时对 `enabled` 状态的现有筛选语义。
- 不改变流程图的停用状态和停用流转视觉样式。

## 方案比较

### 方案一：仅根据端点状态动态推导

流转任一端状态停用时视为停用，两端恢复后自动启用。该方案无需新增字段，但无法区分手工停用和联动停用，会误恢复用户明确停用的流转。

### 方案二：在 `ui_config` 中保存联动标记

使用隐藏键记录流转是否因状态停用。该方案无需数据库迁移，但 `ui_config` 属于按钮展示配置，可能被“清空按钮配置”或后续配置清洗覆盖，且业务可用性原因与展示配置职责不一致。

### 方案三：增加专用持久化字段

在 `workflow_transitions` 增加 `auto_disabled_by_state` 布尔字段，明确记录停用原因。该方案需要一次向前兼容的数据库迁移，但数据语义清晰，能够在前端、API 和后端保存逻辑之间稳定往返。

采用方案三。

## 数据模型

`workflow_transitions` 新增：

- `auto_disabled_by_state BOOLEAN NOT NULL DEFAULT FALSE`

字段含义：

- `false`：流转未因状态停用而自动停用；流转可能启用，也可能由用户手工停用。
- `true`：流转最近一次由状态可用性联动停用；仅当来源状态和目标状态均恢复启用时才允许自动恢复。

既有数据迁移时统一填充 `false`，避免将历史手工停用流转误判为可自动恢复。

## 联动规则

对每条流转读取来源状态和目标状态：

1. 任一端状态停用且流转当前启用时，将流转设为停用，并设置 `auto_disabled_by_state=true`。
2. 任一端状态停用且流转已经手工停用、标记为 `false` 时，保持原值，不增加自动标记。
3. 任一端状态仍停用且标记已经为 `true` 时，保持停用和标记。
4. 两端状态均启用且标记为 `true` 时，将流转恢复启用，并清除标记。
5. 两端状态均启用且流转为手工停用时，保持停用。

布尔标记足以覆盖两端先后停用的情况，因为恢复动作必须等待两个端点都启用。

## 前端设计

状态抽屉移除“删除状态”按钮，保留状态名称、类型、颜色和启用开关。状态开关不再直接修改对象字段，而是触发父设计器的状态启停处理函数。

父设计器更新状态后，通过纯函数对全部关联流转应用联动规则。流转对象的 `enabled` 和 `auto_disabled_by_state` 立即更新，因此现有画布无需重新请求即可把停用流转渲染为灰色虚线。

流程图投影继续包含停用流转，不增加按 `enabled` 过滤。流转高级配置中的启用开关在任一端状态停用时禁用，并显示当前流转由状态可用性约束，防止用户创建临时不一致状态。

## 后端设计

工作流图保存服务在业务校验前统一规范化流转可用性：根据同一载荷中的状态启用值应用联动规则，再执行重复名称、配置结构和图形路径校验。规范化后的 `enabled` 和 `auto_disabled_by_state` 一并持久化并返回。

后端校正是最终一致性边界，能够覆盖旧前端、直接 API 调用和前端状态不同步。运行时继续只使用启用流转，无需增加分支。

## 兼容性与异常处理

- 旧客户端未提交新字段时，API 使用默认值或保留数据库现值，不能把既有自动标记无意清除。
- 新增流转默认 `auto_disabled_by_state=false`；如果端点状态停用，保存规范化会将其停用并设置标记。
- 既有异常数据中启用流转指向停用状态时，下一次保存会自动修正。
- 数据库迁移仅新增非空默认字段，不修改现有流转启停值。

## 测试设计

前端纯函数测试覆盖：

- 状态停用会停用所有关联的启用流转并设置标记。
- 停用流转仍保留在输入集合中，供画布虚线展示。
- 手工停用流转不增加标记。
- 仅恢复一个端点时不恢复流转。
- 两端都恢复时仅恢复带自动标记的流转。
- 输入集合和无关流转不被意外修改。

前端组件契约测试覆盖：

- 状态抽屉不再包含“删除状态”按钮。
- 状态启用开关调用联动处理函数。
- 流转启用开关在任一端状态停用时不可操作。
- 画布继续为停用流转应用 `disabled` 虚线样式。

后端 API 测试覆盖：

- 保存停用状态时自动停用关联流转并持久化标记。
- 恢复两端状态时自动恢复联动停用流转。
- 单端仍停用时保持流转停用。
- 手工停用流转在状态恢复后仍保持停用。
- 旧载荷和新字段能够正确往返。

数据库迁移测试覆盖字段默认值、升级和降级行为。
