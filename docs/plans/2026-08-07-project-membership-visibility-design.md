# 项目成员可见范围设计

## 目标

项目成员资格是项目数据可见性的前置条件。业务组件成员资格只能在用户已经属于组件所属项目时参与工作流路由，不能隐式授予项目、工作项或组件的查看权限。

## 授权模型

- 系统管理员可查看全部项目数据。
- 项目成员可查看所属项目及其工作项、测试、迭代和业务组件。
- 已被授予项目治理权限的项目负责人、父项目负责人和项目集治理人可查看其治理范围内的数据。
- 其他已登录用户无权查看该项目及其关联资源；直达详情接口返回 403，列表和搜索结果不返回该数据。

## 组件成员策略

创建维护组件时不再自动复制来源项目成员到目标项目或组件。项目负责人需要先显式维护目标项目成员，再将已具备项目成员资格且拥有所选后台角色的用户加入组件。已有的组件成员写入校验继续拒绝非项目成员。

## 实现边界

在后端权限服务中集中提供项目可见范围和单项目查看校验。项目、需求、任务、Bug、测试、迭代和组件的列表服务使用同一可见范围过滤；详情和项目子资源端点执行同一校验。前端不在客户端补偿权限判断，只消费后端已过滤的数据。

## 错误处理与验证

未授权详情返回中文 403 错误。通过 API 回归覆盖：非成员看不到列表项、无法直达详情、成员和系统管理员仍可访问，以及创建组件不再复制来源成员。验证后将问题清单 N-001 更新为已解决并记录测试证据。
