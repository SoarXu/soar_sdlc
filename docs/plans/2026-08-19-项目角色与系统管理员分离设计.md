# 项目角色与系统管理员分离设计

## 目标

后台用户管理只维护账号及系统管理员资格。后台角色管理维护业务角色字典；业务角色的人员归属只在项目成员中设置，并由项目上下文参与权限和工作流判断。

## 权限边界

- 全局角色唯一为 `system_admin`，用于后台访问和跨项目管理。
- 产品、研发、测试、项目负责人等业务角色只来自 `project_members.project_role`。
- 项目负责人字段仍代表项目责任人；不再从全局业务角色推导项目负责人。

## 接口与数据

用户读取返回 `is_system_admin`。新增和更新用户权限仅接收该布尔值，服务端只维护 `system_admin` 关联。角色字典及其新增、编辑、停用 API 保留，供项目成员和工作流模板选择；运行时不再读取用户的全局业务角色。

数据迁移删除 `user_roles` 中所有非系统管理员关联。项目成员记录不变，因此既有项目中的业务权限与工作流角色不受影响。

## 页面

后台保留“用户”和“角色”两个页签：用户页仅显示和维护“系统管理员”开关；角色页维护业务角色字典。项目成员的角色下拉框读取已启用的业务角色，排除 `system_admin`，并兼容展示历史角色值。

## 验证

后端覆盖系统管理员开关、全局业务角色不参与项目权限、迁移清理。前端覆盖用户页不出现角色多选、角色页可维护角色字典、项目成员角色来源于角色字典。所有测试只使用现有白名单账户或不创建用户的纯函数/接口夹具。
