# 后续问题清单

## 使用范围

本文档用于登记 SOAR SDLC 平台后续发现、尚未解决的问题。每一个问题必须先完成复现和影响确认，再建立对应的中文执行计划；未经验证不得标记为已解决。

## 问题状态

- 待确认：已收到现象，尚未稳定复现或确认影响。
- 待计划：已确认问题，等待制定执行计划。
- 待实施：计划已确认，等待集中处理。
- 实施中：正在修复或补充自动化测试。
- 待验证：实现已完成，等待回归与验收。
- 已解决：验证通过，保留问题、计划和验证证据。

### N-001 创建项目默认生成迭代，且需求创建缺少可用迭代约束

- 状态：已解决
- 类型：功能与数据一致性问题
- 优先级：P2
- 发现时间：2026-08-18
- 影响范围：项目创建、项目迭代列表，以及需求创建入口。
- 复现步骤与证据：创建项目后进入项目详情的“迭代”页。截图显示项目“小样纯化”存在系统生成的“待规划迭代”，状态为“规划中”。
- 预期结果：创建项目时不自动创建任何迭代。创建需求时，必须关联该项目中状态为“规划中”或“进行中”的迭代；当不存在此类迭代时，禁止创建需求并提示用户先创建可用迭代。
- 实际结果：项目创建后存在“待规划迭代”。

- 执行计划：移除项目创建流程中的自动迭代创建；保留需求 API 的迭代必填和状态范围校验，以及前端需求表单对可用迭代的筛选和必填校验。
- 验证结果：新增项目创建零迭代回归测试，先确认旧实现失败，再移除自动创建调用后通过。后端定向 `python -m pytest tests/test_requirement_real_iteration_assignment_api.py::test_project_creation_does_not_provision_a_default_iteration tests/test_requirement_real_iteration_assignment_api.py::test_requirement_create_requires_explicit_iteration tests/test_requirement_real_iteration_assignment_api.py::test_requirement_create_accepts_only_eligible_project_scoped_iteration -q` 通过（4 passed），覆盖新项目无迭代、需求缺少迭代拒绝、项目范围外或已关闭迭代拒绝、规划中和进行中迭代接受；`python -m compileall -q app/services/project_service.py app/services/requirement_service.py app/services/iteration_assignment_service.py` 通过。前端 `node src/views/requirementRealIterationAssignment.test.mjs` 通过，生产构建 `npm run build` 通过（1779 modules transformed）；验证未创建测试用户。

- 影响范围：需求、任务和 Bug 的工作流配置、流转按钮可见性、下一状态处理人解析及项目成员配置。
- 复现步骤与证据：将需求流转至“待确认”后，当前处理人因下一步角色在项目成员中未匹配而为空。该需求的“确认”流转已配置允许“当前处理人、项目负责人”执行，项目负责人登录工作台后仍只看到“更多”，没有“确认”按钮。现场数据确认项目负责人角色校验和处理范围校验均通过，但该流转的内部 `requires_owner=true` 因当前处理人为空而将按钮隐藏。
- 预期结果：允许执行角色与当前处理人规则独立判断。处理范围为“允许角色”时，已获授权的项目负责人等角色可在当前处理人为空时看到并执行流转；“必须已有当前处理人”仅约束“仅当前处理人可操作”的流转。
- 实际结果：内部处理人存在性规则优先隐藏按钮，即使项目负责人已在允许执行角色中，仍无法看到或执行“确认”，造成工作流停滞。
- 根因分析：流转按钮可见性同时受 `requires_owner`、处理范围和允许角色控制，但 `requires_owner` 为隐藏的内部配置，未与“允许角色”语义协调；下一状态处理人未解析成功时也缺少预检和兜底策略。
- 执行计划：将 `requires_owner` 的适用范围限制为“仅当前处理人”流转；在执行进入下一状态前解析处理人，目标状态要求处理人但无可用成员时阻止流转并说明所需角色；在配置界面增加“无人匹配时”策略（阻止并提示、自动指派项目负责人、手动选择项目成员）；保存工作流时校验“无处理人且无兜底”与后续处理人必填节点的冲突；所有自动兜底和手动指定均写入操作历史。
- 验证结果：待实施。

### N-014 变更工作流流转目标状态后遗留路由导致流程图无法保存

- 状态：已解决
- 类型：功能与体验问题
- 优先级：P1
- 发现时间：2026-08-18
- 影响范围：工作流设计器的流转基础配置、流程图自动布线配置及流程图保存接口，当前已在缺陷工作流中复现。
- 复现步骤与证据：在缺陷工作流中选择“验证不通过”流转，将目标状态从“待处理”改为“修复中”后保存流程图，页面提示“无效图形配置”。现场数据确认该流转保存的自动布线配置原路径为 `(1134,208) -> (430,208) -> (430,489) -> (81,489) -> (81,121)`，原目标校验通过；仅改为“修复中”后，末段变为 `(81,489) -> (527,121)` 的斜线，后端校验稳定拒绝。
- 预期结果：修改流转的来源或目标状态时，系统自动重新计算自动布线路径，或清除旧的自动路由并在保存时按新端点生成；手工布线存在时，应明确提示用户重置或重绘该连线，不能以“无效图形配置”阻断保存。
- 实际结果：前端只更新 `to_state_id`，保留旧 `diagram_config`；后端按新目标节点重新计算锚点后发现旧拐点无法形成正交连线，返回未说明原因的“无效图形配置”。
- 根因分析：流转目标状态下拉框未联动清除或重算 `diagram_config`。即使配置标记为自动布线，已保存的锚点和拐点仍会随请求提交；后端要求从来源锚点、全部拐点到目标锚点的每一段均严格水平或垂直，端点变化使遗留路径失效。
- 执行计划：在前端监听来源或目标状态变化：自动布线配置立即失效并按新端点重建，手工布线配置提示用户重置或重绘；保存前增加本地正交路径校验并给出具体连线名称和操作指引；后端对可识别的陈旧自动布线配置提供可读错误或安全重算兜底；补充自动与手工布线在变更端点后的保存回归测试。
- 验证结果：后端 `python -m pytest tests/test_workflow_definition_api.py::test_save_graph_clears_stale_generated_route_after_transition_target_changes tests/test_workflow_definition_api.py::test_save_graph_round_trips_transition_diagram_config tests/test_workflow_definition_api.py::test_save_graph_rejects_invalid_transition_diagram_config -q` 通过（11 passed）；前端 `node src/utils/workflowManualRoute.test.mjs`、`node src/components/workflowDesignerDrawerIntegration.test.mjs` 和 `node src/components/workflowAdvancedConfigDrawer.test.mjs` 通过，覆盖变更端点清除旧路径、手工路径确认和组件事件接线。手工路径异常提示更新为“图形路径无效，请恢复自动布线或重新绘制路径”。

### N-013 工作项评审仅支持 DevOps 自动触发且待评审缺少统一评审入口

- 状态：待实施
- 类型：功能与体验问题
- 优先级：P1
- 发现时间：2026-08-18
- 影响范围：需求、任务和 Bug 的“提交评审”“待评审”工作流节点，DevOps 提交关联、工作台、项目详情列表和工作项详情页。
- 复现步骤与证据：Bug 处于“修复中”时，工作流图存在“提交评审”连线，但工作台不显示该按钮。现场数据确认该流转配置为 `system_action`，工作台接口会过滤系统动作；现有评审仅在 DevOps 接收到关联提交后自动创建，且待评审页面没有统一的 Diff 查看和评审决定弹窗。
- 预期结果：需求、任务和 Bug 均支持当前处理人手动点击“提交评审”，也支持 DevOps 关联提交自动触发；待评审时，获授权角色仅看到“评审”按钮。点击后弹窗展示关联 Git Diff；没有关联提交或 Diff 为空时显示“未找到 Git Diff 片段”。弹窗提供“评审通过”和“评审不通过”：通过进入对应待验证状态；不通过必须填写理由并回到处理中或修复中。
- 实际结果：提交评审仅能由 DevOps 自动触发，工作流图与工作台可操作性不一致；现有评审决定分散在工作台和 DevOps 页面，手动提交且无 Diff 的场景无法形成可追溯评审。
- 根因分析：`submit_review` 被标记为系统动作并在可用流转接口中排除；评审记录要求关联提交，且现有 UI 未将通过、驳回聚合到同一评审上下文弹窗。

- 验证结果：待实施。
