# 工作项状态矩阵验证计划

## 验证依据

| 编号 | 来源 | 可验证规则 |
| --- | --- | --- |
| V-01 | N-002 问题清单 | 创建状态由处理人和迭代阶段共同决定。 |
| V-02 | 状态矩阵设计 | 未分派、待开始、执行中使用稳定状态角色而非中文名称。 |
| V-03 | 工作流运行时 | 迭代启动及移动的自动状态变化必须产生正式历史。 |
| V-04 | N-004/N-005 前置约束 | Bug 动作和任务层级后续改造只能依赖稳定角色。 |

## 自动化验证

| 编号 | 场景 | 步骤 | 预期结果 |
| --- | --- | --- | --- |
| M-01 | 角色持久化 | 保存带三个状态角色的需求图，再读取图。 | 角色原样返回；重复角色或非适用角色返回 422。 |
| M-02 | 默认与旧图迁移 | 对默认和可识别旧图执行迁移/协调两次。 | 只产生一个待开始状态和一条系统启动流转，第二次无额外变化。 |
| M-03 | 无处理人创建 | 分别在未开始和进行中迭代创建需求、任务、Bug。 | 均为 `unassigned`，无可执行的工作中按钮。 |
| M-04 | 有处理人创建 | 分别在未开始和进行中迭代创建需求、任务、Bug。 | 未开始为 `waiting_iteration`；进行中为 `active_work`，并返回对应流转按钮。 |
| M-05 | 指派与取消指派 | 在两种迭代阶段执行认领/指派，再执行取消指派。 | 指派目标符合阶段；取消后处理人为空且回到 `unassigned`，均有状态操作记录。 |
| M-06 | 启动迭代 | 在同一未开始迭代准备无处理人和待开始的三类工作项后启动。 | 无处理人保持未分派；待开始项进入执行角色并产生 `start_iteration` 历史。 |
| M-07 | 移动迭代 | 待开始项移入进行中迭代；执行中项移入未开始迭代。 | 前者自动启动并记历史；后者被 409 阻断，成员关系和状态均不改变。 |
| M-08 | Bug 保护 | 启动包含待开始 Bug 的迭代。 | 迭代先进入进行中后再启动 Bug，不触发“Bug 所属迭代未进行中”错误。 |
| M-09 | 前端状态配置 | 在三种工作流图中设置角色并保存；在项目/迭代图中查看抽屉。 | 前三者显示选择器并回写；后两者不显示。 |

## 回归与验收

- `pytest`：状态角色迁移、工作项状态矩阵、工作流定义、工作流运行时、默认模板、迭代历史和创建接口相关用例。
- `npm test`：状态角色工具、工作流抽屉契约及既有前端套件。
- `npm run build`：Vue 模板与生产打包。
- 手工验收：以未开始和进行中迭代各创建一条需求、一条任务和一条 Bug，确认列表状态文字、详情状态及流转按钮均与矩阵一致。
