# 项目集名称唯一性设计

## 规则

- 顶层项目集之间名称唯一。
- 同一父项目集下名称唯一；不同父项目集下允许同名。
- 已软删除项目集不占用名称。
- 保存时移除名称首尾空格，并按不区分大小写的方式比较。

## 实现边界

项目集仍保存原始展示名称；服务层在创建、改名和变更父项目集前统一规范化名称，
并在冲突时返回可读的 422 错误。数据库同时提供最终一致性保护，避免并发请求绕过
服务层检查。

MySQL 不支持部分唯一索引，且普通复合唯一索引无法把 `parent_id IS NULL` 的顶层
项目集视为同一个作用域。因此为 `programs` 增加两个存储生成列：有效记录的父级
作用域 ID（顶层映射为 0）和有效记录的规范化名称；已删除记录的两个值均为 NULL。
在两个生成列上建立唯一索引。NULL 不参与唯一比较，因而软删除记录可复用名称。

SQLite 测试环境由服务层验证覆盖语义；MySQL 运行时 schema 初始化和 Alembic 迁移
负责建立生成列与唯一索引。

## 验收

- 创建或改名为同一作用域的同名项目集被拒绝，错误说明重复作用域。
- 不同父级下的同名项目集可以保存。
- 顶层同名项目集被拒绝。
- 软删除后可用同名重新创建。
- 名称仅首尾空格不同或大小写不同视为重复。
- 将项目集移动到产生名称冲突的父级时被拒绝。
- MySQL schema 中存在对应生成列和唯一索引。
